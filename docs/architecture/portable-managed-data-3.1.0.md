# V3.1.0 の管理データJSON

[W10 #688](https://github.com/Tao-pyth/master-duel-recorder-lite/issues/688)の形式・検証・隔離DB材料化の設計です。本番DBの置換とバックアップ・管理排他はW11が担当します。

新形式は`mdrl-managed-data-v2`です。戦績・録画履歴・既存カタログに、対戦カード正本・初動・確認履歴・必要なカード同一性と解析対象設定、完了YouTube投稿のURL/video_id、一般／カードマーカーと動画世代・時刻基準・指紋、確定削除理由／日時、保護状態を加えます。解析対象設定はカードマーカーの参照先として持ち出し、解析ジョブは含めません。

動画ファイル、MP4、OAuth、送信待ち、解析job/checkpoint、削除intent、投稿後再試行要求、現在の動画利用記録は持ち出しません。完了投稿の準備キュー参照と観測のjob参照を切り離し、削除履歴の回復用metadataを持ち出しません。外部の絶対動画パスは保存先内の相対パスへ変換し、保存先外の参照は拒否します。

JSON内の表・列・型・日時・ID重複・参照関係・使用と初動の整合を、実行処理を持たない隔離SQLiteで検証します。未許可の表、未完了投稿、job参照、資格情報を含む構造は取込計画を作る前に拒否します。ファイルがあるかどうかを取込成功の条件にせず、物理削除・アップロード・解析を起動しません。

持ち込んだ動画の利用状態は、確定削除済みを除いて`unverified`へ戻します。マーカーはすべて`verified=0`とし、内容・動画世代・時刻基準の一致を製品側で確認するまで利用不可です。パスや録画IDだけでは再有効化しません。

旧`mdrl-managed-data-v1`を受け入れ、旧対戦ID・廃止済みコイントス列・シーズン既定値・保存済みフィルター欠落を従来どおり補完します。追加されたカード・投稿・削除情報の欠落は未登録のままです。動画管理行は未確認・保護falseとして構成し、使用・非使用・投稿完了・削除理由を推定しません。

共有カードと解析対象のID対応は取込計画へ明示します。同じ正規化名は既存IDを利用し、同じIDが異なるカードを指す場合は持込側へ別IDを割り当て、正本・初動・観測・履歴内の関連をまとめて更新します。既存共有設定を保つ本番置換はW11で行います。

材料化APIは管理行がない隔離DBだけを受け付けます。すでに利用者情報があるDBを置換しません。DBへの書込みも一transactionで行い、失敗時は空の状態へrollbackします。
