# PySide6 UI Usability Recovery 2.3.0

## Purpose

V2.3.0では、V1.xで成立していた実操作がPySide6 GUIで表示だけになっていた箇所を、既存サービス層へ再接続する。DADSはQtへ直接移植せず、操作領域、状態表示、日付選択、進行中表示、主操作と補助操作の分離という考え方を取り入れる。

## Scope

- 左下ステータスは固定文言ではなく `RecorderApplicationService.diagnose()` の結果から表示する。
- 録画画面の開催中シーズンは `active_season_summaries()` から取得し、なし、注意、取得失敗を区別する。
- デッキ名、タグ、シーズンは一覧選択、フォーム反映、追加、保存、削除またはアーカイブをGUIから実行できる。
- テンプレート画面は投稿テンプレート編集と準備キューに限定し、YouTube接続管理は設定画面へ集約する。
- 信頼性画面は状態更新と初回導入確認をクリック後に表示へ反映する。
- YouTube投稿はGUIスレッドで同期実行せず、バックグラウンド実行器で処理し、二重実行を抑止する。

## UI Rules

- ボタン、入力、プルダウン、日付入力は最小高さ36pxへ揃える。
- 日付入力は `QDateEdit` のカレンダーポップアップを使う。
- カラー列は色コードを主要表示にせず、色見本と短いラベルで表現する。
- 選択色とデータ色を混同させないため、表セル全体をデータ色で塗らず、DecorationRoleでスウォッチ表示する。
- 長時間処理は `ThreadPoolExecutor` と `QTimer` のポーリングで完了、失敗をUIへ戻す。永続ジョブ管理、キャンセル、詳細な再試行ポリシーは対象外とする。

## Verification

- `smoke_contract()` に固定状態表示、開催中シーズン、編集保存、テンプレート責務、信頼性操作、バックグラウンド処理、UI高さの契約を追加する。
- `tests/test_pyside_gui.py` と `tests/test_v201_gui_recovery.py` で契約が欠けた場合に検出する。
- PySide6 GUI smokeでデッキ名、シーズン、テンプレート、信頼性画面のスクリーンショットを確認する。
