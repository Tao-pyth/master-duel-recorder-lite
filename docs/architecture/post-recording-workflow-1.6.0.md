# 録画後ワークフロー情報設計

## 目的

V1.6.0では、V2.0.0のPySide6全面移行へ入る前に、録画後の整理、振り返り、投稿準備を1つの作業導線として固定する。目的は新しい画面実装ではなく、Tkinterの複雑な画面構成をそのままQtへ移すことを避け、Master Duel専用ツールとして重要な流れを設計前提にすることである。

入力資料は`docs/architecture/tkinter-ui-baseline-1.5.2.md`と保存済みPNGである。V1.6.0ではDB schema、設定形式、録画ファイル、queue、manifest、OAuth資格情報を変更しない。

## 録画後ハブ

録画後に利用者が最初に戻る場所は、戦績管理ページとする。戦績管理は単なる一覧ではなく、次の作業を判断するハブとして扱う。

| 状態 | 優先度 | 利用者に見せる情報 | 主操作 | 補助操作 | 危険操作 |
| --- | --- | --- | --- | --- | --- |
| 未入力録画 | 1 | 開始日時、録画有無、未入力、ファイル状態 | 戦績を入力 | 再生、レビュー、後回し | 削除 |
| 下書き戦績 | 2 | 下書き、未設定項目、録画有無 | 未完了を処理 | 詳細編集、タイムライン | 削除 |
| 録画欠損 | 3 | 欠損理由、元の録画ID、戦績状態 | 診断を表示 | 再関連付け、保存場所確認 | 削除 |
| 確認済み未投稿 | 4 | 勝敗、デッキ、シーズン、投稿状態 | YouTube投稿 | レビュー、クリップ出力 | 削除 |
| 投稿済み | 5 | YouTube URL、投稿日時、戦績概要 | リンクを開く | 再生、レビュー | 削除 |
| 録画なし手動戦績 | 6 | 登録元、勝敗、デッキ、シーズン | 編集 | 統計確認 | 削除 |

主要操作は「未完了を処理」「戦績編集」「録画再生」「レビュー」「YouTube投稿」とする。補助操作はフィルター、列表示、重複比較、タイムライン、診断、保存場所表示に分ける。削除、初期化、再関連付け、public投稿、復元、更新適用は危険操作として通常ボタン群から視覚的に分離する。

状態表示は色だけに依存しない。勝敗、先後、コイン、録画状態、投稿状態、警告は必ず文言でも確認できるようにする。

## 代表シナリオ

| シナリオ | 開始点 | 期待される流れ | 失敗時対応 |
| --- | --- | --- | --- |
| 対戦直後に戦績を入れる | 録画完了後または戦績管理の未入力行 | 簡易入力で勝敗、先後、コイン、相手デッキを保存し、必要なら詳細入力へ進む | 保存競合は再読込、期間外シーズンは確認、入力エラーは保存しない |
| 未完了をまとめて処理する | 戦績管理の未完了件数 | 未完了キューで前へ、後回し、下書き保存、詳細入力を選ぶ | キュー再読込後も本番DBを壊さず、処理済み項目は一覧から外れる |
| 過去録画を振り返る | 戦績管理の確定済み行 | 再生、PySide6レビュー、タイムライン、現在位置マーカー、クリップ出力へ進む | 録画欠損は診断と再関連付けへ誘導し、元レコードを削除しない |
| 投稿前に確認する | 戦績管理の投稿可能行 | テンプレート展開、MP4準備、private投稿、投稿済みURL保存を確認する | OAuth未接続は接続へ誘導、quota/rateは待機、public投稿は追加確認 |
| 投稿済みを確認する | 戦績管理の投稿済み行 | YouTubeリンクを開き、戦績とURLを確認する | URLが保存済みなら再投稿を既定で禁止する |

## `prepare`内部ページの扱い

`prepare`はV1.4.1以降、主要ナビではなくYouTube投稿前処理に統合する方針である。V2.0.0では独立ページとして移植しないことを既定とし、機能ごとに次へ分解する。

| 機能 | V2.0.0での扱い | 理由 |
| --- | --- | --- |
| 録画選択 | YouTube投稿ダイアログ内 | 投稿対象を録画ID手入力に戻さないため |
| タイトル、概要欄、タグ | YouTube投稿ダイアログとテンプレートページ | 投稿直前確認とテンプレート管理を分けるため |
| キュー追加 | YouTube投稿フロー内 | MP4準備だけを利用者が単独実行する必要性が低いため |
| 待機中実行 | 内部処理またはCLI | queue互換は維持し、GUI主要導線には出さないため |
| キュー一覧 | 診断または設定の補助情報 | 失敗確認用であり、日常操作の中心ではないため |

prepare queue、manifest、exportsの形式は変更しない。内部ページを削除しても実行時データ削除を意味しない。

## `improve`内部ページの扱い

`improve`は未成熟な主要ナビとして露出しない方針を維持する。V2.0.0では独立ページとして移植しないことを既定とし、次の移行先へ吸収する。

| 機能 | 移行先 | 理由 |
| --- | --- | --- |
| 録画なし戦績追加 | 戦績管理ハブ | 録画後整理と同じ入力導線で扱うため |
| 入力候補 | 戦績入力ポップアップ | 候補は入力時に必要な情報であるため |
| デッキ改善集計 | 統計ページ | 分析結果は統計と同じ利用文脈であるため |
| ストレージ候補 | 設定の管理データまたは診断 | 危険操作へ近く、通常分析から分けるため |
| 移行パック | 設定の管理データ | バックアップ、復元、入出力と同じ責務であるため |
| 軽量レビュー入口 | 戦績管理ハブ | 対象行から直接レビューするほうが自然なため |

削除や統合はUI導線の整理であり、SQLite、録画、queue、manifestを削除しない。

## 設定画面の再編

PySide6移行時の設定は、リスクの近い操作を同じ領域にまとめる。

| 領域 | 含める操作 | 分離理由 |
| --- | --- | --- |
| 通常設定 | FFmpegパス、録画品質、音声入力、自動判定、通知、表示 | 変更してもデータ削除に直結しない |
| 外部連携 | YouTube連携、切断、接続確認、privateテスト投稿 | OAuth状態と投稿状態を通常録画設定から分ける |
| データ保護 | 保存先変更、バックアップ、復元、管理データ入出力、CSV | 既存DBや録画に影響するため確認と結果表示が必要 |
| 危険操作 | 初期化、削除、クリーンアンインストール、public投稿、更新適用 | 確認語、影響範囲、キャンセル時無変更を必須にする |
| 診断 | 環境診断、整合性確認、ログ、queue確認 | 失敗原因の共有と再確認をしやすくする |

危険操作では、対象、影響範囲、バックアップ有無、取り消し可否を表示する。キャンセルではDB、設定、録画、queue、OAuth資格情報を変更しない。OAuth token、refresh token、client secret、認可コードは表示、保存、ログ出力しない。

## ダイアログ導線

ダイアログを減らすこと自体は目的ではない。保存、キャンセル、後回し、詳細入力、失敗表示、危険操作確認の契約を落とさず、必要なものだけページ内パネルまたはモーダルへ移す。

| 導線 | 推奨形 | 維持する契約 |
| --- | --- | --- |
| 戦績管理フィルター | 右パネルまたはモーダル | 保存済み条件、解除、複数タグ、キャンセル時無変更 |
| 簡易入力 | モーダルまたはページ内クイック編集 | 勝敗、先後、コイン、相手デッキ、後回し、詳細入力 |
| 未完了処理 | 専用ワークフローモーダル | 前へ、後回し、下書き、保存して次へ、詳細入力復帰 |
| 詳細入力 | 大型モーダルまたは詳細パネル | 録画状態、YouTube URL、タグ、シーズン期間外確認 |
| 一括編集 | モーダル | 変更しない、未設定、適用前確認、タグ追加・削除 |
| タイムライン | レビュー画面または大型モーダル | candidate/confirmed/rejected、手動マーカー、録画時刻 |
| YouTube投稿 | モーダル | 投稿前確認、private既定、public追加確認、投稿済み再投稿禁止 |
| 診断 | 大型モーダル | 長文コピー、secret伏せ字、失敗を成功扱いしない |
| クリーンアンインストール | 危険操作モーダル | 確認語、削除範囲、録画/監視停止確認、キャンセル時無変更 |

## スクリーンショット回帰と操作スモーク

V2.0.0では、画面単体だけでなくワークフロー単位の検証を追加する。

| 検証データ | 必須状態 |
| --- | --- |
| 空データ | 初回表示、未完了0件、候補なし、投稿なし、シーズンなし |
| データ入り | 録画あり、録画欠損、手動戦績、下書き、確認済み、投稿済み、デッキ色、タグ、シーズン |
| OAuth未接続 | 連携開始可能、secret非表示、投稿不可理由 |
| OAuth接続済み相当fake | 投稿前確認、投稿済みURL、重複投稿防止 |
| queueあり | waiting、processing復帰、failed、completedの表示 |

スクリーンショット保存先案は`docs/assets/pyside6-ui-2.0.0/`とし、`01-record-empty.png`、`02-history-rich.png`のようにページ番号、画面名、状態を含める。ポップアップは`docs/assets/pyside6-ui-2.0.0-popups/`へ分ける。

操作スモークは、起動、終了、ページ切替、戦績入力保存、未完了処理、録画再生起動可否、レビュー起動可否、YouTube投稿ダイアログ、設定危険操作キャンセル、診断コピー、保存先変更キャンセルを含める。本番`user_data`は使わず、検証用runtimeと必要に応じたDBコピーだけを使う。
