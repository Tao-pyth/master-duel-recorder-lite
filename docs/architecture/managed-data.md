# 管理データの入出力・初期化

V3.1.0の新形式は`mdrl-managed-data-v2`です。録画履歴・戦績・管理カタログに加え、対戦カード情報・明示非使用・初動・確認履歴・必要なカードID、完了YouTube投稿のURL/video ID、一般/カードマーカーと動画の同一性、確定削除理由・日時、保護を含めます。旧`mdrl-managed-data-v1`も受け入れ、追加情報の欠落を非使用・完了・削除理由へ推定しません。

動画ファイル・MP4・OAuth・送信待ち・解析job/checkpoint・未完了削除intent・投稿後再試行要求・現在の利用leaseは持ち出しません。許可する表・列・型・日時・ID・参照を隔離SQLiteで検証し、禁止実行情報を含むJSONは拒否します。完了URLや削除履歴から新しい実行要求を作りません。[形式の詳細](portable-managed-data-3.1.0.md)を参照してください。

インポートは現在の管理データを置き換えます。検証済みバックアップと共通管理gateの下で、共有カードID等を対応付け、対象の関連行を子から親へ処理して同じtransactionで置換します。途中失敗は全変更をrollbackし、設定・実ファイルを変更しません。共通カード・解析対象設定を保持し、必要な情報だけ追加します。戻ったマーカーは内容・動画世代・時刻基準の一致まで未検証とします。

初期化は履歴、デッキ、タグ、シーズン等を指定できます。GUIでは確認ダイアログと確認文字列を使います。履歴・全体初期化は対象戦績・カード情報・初動・マーカー・job・ローカル投稿・削除管理等を所有者別に処理します。自由記述タグだけの初期化は対戦カード情報を消しません。デッキ・タグ・シーズンは関連参照を解除してから処理します。JSON取込・初期化は録画保存先の動画、MP4、YouTube上の投稿、OAuthを削除しません。[管理操作の詳細](owned-data-management-3.1.0.md)を参照してください。

録画・自動監視・元動画利用・準備/投稿/解析の実行中は管理置換を拒否します。未完了削除があれば通常GUI起動で回復してから操作します。プレビューと診断は実行指示を消費しません。
