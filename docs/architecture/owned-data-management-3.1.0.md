# V3.1.0 の完全削除・初期化・JSON取込

[W11 #689](https://github.com/Tao-pyth/master-duel-recorder-lite/issues/689)の所有者別DB操作です。動画だけの削除はW3の共通サービスを使い、対戦カード正本・投稿URLを保持します。

完全削除では、対象対戦の確認履歴・初動・カード正本・タグ・戦績変更履歴、対象録画の観測・一般マーカー・解析job・投稿後要求・ローカル投稿・削除監査・動画世代・保護を子から親へ消します。共通カード・解析対象設定・他対戦・YouTube上の動画・MP4／clip／キューファイル・OAuthは消しません。

DB操作は明示transactionを必須にし、途中で失敗すれば一括rollbackします。動画処理の共通排他、録画排他、未完了journal・現在の利用・実行中処理のgateを通してから、検証済みバックアップを作ります。

録画付き完全削除は同じ削除サービスの`retained_backup`を動画削除とDB関連削除の完了まで共有します。処理中は通常世代を必須保持し、`data-protection.lock`とlive SHA確認で実在を保証します。終了後は通常ローテーションへ戻し、完全削除ごとに恒久保護世代を増やしません。移行・復元の事前バックアップは保護世代を維持します。

録画付き完全削除は、原動画の境界・同一性・共有参照・保護を検証し、W3のdurable journalで物理削除を確定させた後、DBの関連行と録画を削除します。unlinkに失敗すれば退避ファイルを戻し、DB全削除へ進みません。物理削除成功後にDB全削除が失敗した場合は、戦績・正本・削除理由を残し、未完了として再操作を案内します。動画本体はバックアップに含まれず、unlink後の復元を保証しません。

JSON取込は、W10の隔離検証を先に行い、管理gateとバックアップ保持の下で共有カード／対象のIDを対応付け、同じtransactionで履歴と管理カタログを全置換します。既存共有カード・解析対象設定は保持し、新しく必要な共有情報だけを追加します。JSONから処理要求を作らず、マーカーは未確認のまま保存します。失敗時はDB transactionをrollbackし、設定や実ファイルを書き戻しません。

history／all初期化でも対戦・録画の所有情報は同じ順序で消し、共通カード／対象設定を保持します。タグ初期化は自由記述タグとそのカタログだけを対象とし、対戦カード情報を消しません。デッキとタグの関連も、それぞれの初期化範囲で先に処理します。
