# Master Duel向け録画補助

## 目的と現在の範囲

V0.16.5ではMaster Duelの実行状態と対戦盤面を録画処理から独立して観測し、高信頼度の盤面を時間方向に確認した場合だけ録画を開始します。開始演出は補助信号であり必須ではないため、開始演出を見逃した場合や対戦途中から監視した場合も開始できます。可視ウィンドウの存在は判定対象の固定にだけ使い、メニュー、デッキ編集、設定画面の表示だけでは録画しません。

## 検出契約

検出器は録画処理へ次の値だけを渡します。

| 値 | 意味 |
|---|---|
| `PRESENT` | 対戦開始を複数フレームで確認した |
| `ABSENT` | 対象ウィンドウが存在しない、または録画中の対象を失った |
| `UNKNOWN` | 対戦開始前、取得失敗、低信頼度などで判断できない |

各観測は0.0から1.0の信頼度、判定理由、タイムゾーン付き時刻を持ちます。状態機械は信頼度閾値未満を `UNKNOWN` として扱い、録画中の不明判定だけでは停止しません。録画処理は画像やWindows APIへ直接依存しません。

## プロセスとウィンドウ監視

Windows APIで実行中プロセスとトップレベルウィンドウを列挙します。実行ファイル名と任意のタイトル部分一致で候補を絞り、可視かつ最小化されていない最大面積のウィンドウを選択します。状態は未起動、ウィンドウなし、最小化、可視、取得エラーを区別します。観測にはPIDとHWNDを含め、開始確認中にどちらかが変わった場合は連続回数を最初から数え直します。録画開始後はそのPID・HWNDを対象として固定し、別ウィンドウを同じ録画へ無条件で引き継ぎません。

未起動・ウィンドウなし・最小化は信頼度0.8の`ABSENT`、APIエラーは`UNKNOWN`へ変換します。可視状態は録画中だけ従来どおり`PRESENT`として停止監視に使います。録画前は同じ観測を開始ゲートへ渡し、対戦開始が未確認なら`UNKNOWN`へ変換します。

## 誤検出抑制と制御

録画前は既定2fpsで判定用フレームを取得します。盤面スコア0.85以上、開始演出スコア0.35以下、結果スコア0.35以下の候補を既定3フレームで合意すると`PRESENT`を1回発行して録画するため、安定盤面の表示から開始までの目安は約1.5秒です。開始演出から5秒以内に盤面へ遷移した場合は盤面閾値0.60以上でも候補にできます。`start_confirmations`はフレーム合意数に使い、最小2です。信頼度は`minimum_confidence`と`visual_minimum_confidence`の高い方を採用します。取得失敗、対象PID・HWNDの変更、ウィンドウ消失では途中の合意を破棄します。

録画開始後は判定用の事前取得を止め、既定1秒ごとのウィンドウ監視へ戻します。`ABSENT`を5回連続で確認すると停止し、反対信号または不明信号は停止確認をリセットします。停止後10秒間は自動再開しません。録画中に別のPID・HWNDへ無条件で切り替えません。

自動録画コントローラーは録画準備、開始、停止、予期しないFFmpeg終了を一つの実行状態として管理します。FFmpeg開始後は出力サイズの増加を確認し、30秒間増加しなければ停止して失敗として記録します。自動開始が失敗した場合は10秒、20秒、40秒と待機時間を増やし、3回連続で失敗した場合はゲーム画面が一度終了するまで再開しません。手動開始・停止APIは連続確認を待たず反映され、`record` コマンドと `watch` は同じOSロックを使うため同時録画を拒否します。`watch` 実行中のCtrl+Cは監視を終了し、実行中の録画へ正常停止を要求します。

## 異常終了の診断

Windowsが返すプロセス終了コードはDWORD値のことがあるため、録画失敗時は元の値、符号付き32bit値、16進値を併記します。例えば`4294967291`は`4294967291 / -5 (0xFFFFFFFB)`と表示します。録画履歴の`detection_reason`には開始時のPID・HWND・クライアントサイズを、`diagnostics_json`には同じ開始情報とFFmpeg stderrの末尾100行を保存します。これらはGUIやCLIの失敗表示から原因を調査するための情報であり、秘密情報や画面画像は保存しません。

## フレーム取得とプライバシー

対象ウィンドウの1フレームをFFmpegからBMPとして取得します。取得データは上限50MiB、タイムアウト5秒で、メモリ内の値としてだけ返し、自動保存しません。録画開始前の取得失敗は`UNKNOWN`として誤開始を防ぎ、それ以前の合意を破棄します。本録画の成否や既存データへ変換しません。

開始ゲートで確定した`duel_start`は、本録画が始まる直前のイベントなので録画経過0ミリ秒の`candidate`としてタイムラインへ保存します。自動で`confirmed`にはしません。保存だけに失敗した場合は本録画を継続します。

画面やゲーム画像をテスト資産、ログ、リポジトリへ保存しません。実画面を使う検証は利用者が明示的に実施する場合だけとし、通常テストでは偽のWindows API結果とBMPバイト列を使用します。

## CLI

```powershell
python -m master_duel_recorder_lite watch --once
python -m master_duel_recorder_lite watch
```

`watch --once`は設定を読み、現在のプロセス・ウィンドウ状態だけを表示します。録画環境のpreflightやフレーム取得、録画開始は行いません。`watch`はpreflight成功後に継続監視し、画面イベント判定が無効なら理由を表示して開始しません。自動監視の録画対象はMaster Duelウィンドウへ固定し、設定画面で選択したデスクトップや任意ウィンドウへ切り替えません。
