# Master Duel向け録画補助

## 目的と現在の範囲

V0.4.0ではMaster Duelの実行状態を録画処理から独立して観測し、安定した観測が続いた場合だけ録画を開始・停止します。標準検出器は可視ウィンドウの存在を対戦候補として扱う第一段階であり、対戦中、メニュー、デッキ編集を画像で識別する機能ではありません。

## 検出契約

検出器は録画処理へ次の値だけを渡します。

| 値 | 意味 |
|---|---|
| `PRESENT` | 対戦候補を確認した |
| `ABSENT` | 対戦候補が存在しない |
| `UNKNOWN` | エラーや低信頼度のため判断できない |

各観測は0.0から1.0の信頼度、判定理由、タイムゾーン付き時刻を持ちます。状態機械は信頼度閾値未満を `UNKNOWN` として扱い、録画中の不明判定だけでは停止しません。録画処理は画像やWindows APIへ直接依存しません。

## プロセスとウィンドウ監視

Windows APIで実行中プロセスとトップレベルウィンドウを列挙します。実行ファイル名と任意のタイトル部分一致で候補を絞り、可視かつ最小化されていない最大面積のウィンドウを選択します。状態は未起動、ウィンドウなし、最小化、可視、取得エラーを区別します。

標準設定では可視状態を信頼度0.7の `PRESENT`、未起動・ウィンドウなし・最小化を信頼度0.8の `ABSENT`、APIエラーを `UNKNOWN` へ変換します。

## 誤検出抑制と制御

既定では1秒ごとに監視し、`PRESENT` を3回連続で確認すると開始、`ABSENT` を5回連続で確認すると停止します。反対信号または不明信号は連続回数をリセットします。停止後10秒間は自動再開しません。

自動録画コントローラーは録画準備、開始、停止、予期しないFFmpeg終了を一つの実行状態として管理します。手動開始・停止APIは連続確認を待たず反映され、`record` コマンドと `watch` は同じOSロックを使うため同時録画を拒否します。`watch` 実行中のCtrl+Cは監視を終了し、実行中の録画へ正常停止を要求します。

## フレーム取得とプライバシー

将来の低頻度な場面分類に備え、対象ウィンドウの1フレームをFFmpegからBMPとして取得するインターフェースを用意しています。取得データは上限50MiB、タイムアウト5秒で、メモリ内の値としてだけ返し、自動保存しません。V0.4.0の標準検出器はこのインターフェースを呼び出しません。

画面やゲーム画像をテスト資産、ログ、リポジトリへ保存しません。実画面を使う検証は利用者が明示的に実施する場合だけとし、通常テストでは偽のWindows API結果とBMPバイト列を使用します。

## CLI

```powershell
python -m master_duel_recorder_lite watch --once
python -m master_duel_recorder_lite watch
```

`watch --once` は設定を読み、現在のプロセス・ウィンドウ状態だけを表示します。録画環境のpreflightやフレーム取得、録画開始は行いません。`watch` はpreflight成功後に継続監視し、自動録画イベントだけを表示します。
