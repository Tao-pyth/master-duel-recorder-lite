# 基本イベント自動判定

## 目的と対象

V0.16.0ではMaster Duel録画中の画面を低頻度で解析し、対戦開始、ターン切り替え、勝敗・対戦終了の候補をタイムラインへ保存します。カード発動、召喚、チェーン、ライフポイント、フェイズの解析は対象外です。

現在の可視ウィンドウ検出はゲーム画面の存在だけを示し、対戦開始とは扱いません。自動判定はMaster Duelウィンドウ録画でだけ有効とし、任意ウィンドウ、モニター、デスクトップ録画では無効理由を表示します。

## 処理構成

```text
対象ウィンドウ -> 低頻度フレーム取得 -> 表示領域正規化
 -> 個別イベント検出 -> 時間方向の合意 -> candidate保存
```

検出器は録画、SQLite、GUIへ直接依存せず、候補の種別、最初の観測時刻、判定理由、信頼度、検出器ID・版だけを返します。[ADR 0001](../adr/0001-offline-visual-backend.md)により、標準ライブラリだけでBMPの輝度、色優勢、エッジ密度を解析する`mdrl.roi-features`を採用しました。文字列に依存しないためUI言語は自動・日本語・英語を同じ処理で扱います。クラウド画像APIは利用しません。

## フレーム取得と負荷制御

録画開始後に専用ワーカーを起動し、最大2fpsで低解像度フレームを取得します。解析中のフレームは1件だけとし、処理が間隔を超えた場合は古いフレームをキューへ蓄積せず破棄します。録画スレッドは解析完了を待ちません。

停止要求、対象ウィンドウ消失、解析タイムアウト、特徴抽出例外ではワーカーだけを停止または一時無効化します。FFmpeg録画の停止理由や成否へ変換しません。アプリ終了時はワーカーを正常終了し、未終了スレッドを残しません。

取得フレームは原則メモリ内でだけ扱い、自動保存しません。証拠画像保存はこの版の標準機能に含めません。ゲーム画像をテスト、ログ、リポジトリへ含めません。

## 表示領域正規化

ウィンドウ内の16:9ゲーム表示領域を推定し、レターボックスを除いて基準座標へ変換します。検出器は基準座標上の関心領域だけを解析します。表示領域を確定できない場合は信頼度を下げず、候補を生成しません。

## イベント判定

`duel_start`は開始演出とデュエル盤面への遷移を組み合わせます。Master Duelウィンドウの表示、メニュー、デッキ編集だけでは生成しません。1録画につき候補を最大1件とします。

`turn_change`はターン変更演出と操作側UIを組み合わせます。手番を確定できない場合も`actor=unknown`で時刻候補を保持できます。同じ表示の継続は重複イベントにしません。

`duel_result`は結果表示と終了画面遷移を組み合わせます。勝敗を確定できない場合は`outcome=unknown`として対戦終了だけを候補化します。1録画につき候補を最大1件とします。

## 時間合意と保存

複数フレームの一致、イベント別クールダウン、許可された状態遷移で誤検出を抑止します。候補時刻は合意成立時ではなく、採用された連続観測の最初の録画経過時刻とします。

- 信頼度0.70未満: 保存しない
- 信頼度0.70以上: `candidate`として保存する
- 自動判定だけで`confirmed`にしない

利用者が確認・編集したイベントを再解析で上書きしません。検出器版が変わった再解析結果は別候補として識別し、既存候補との関係を表示します。

## 設定と診断

有効化、最大fps、UI言語、信頼度閾値を非シークレット設定として検証します。既定はMaster Duel対象で有効、最大2fps、言語自動、閾値0.70とします。preflightはバックエンド、FFmpegフレーム取得、対象モードを確認し、利用不可でも録画自体は許可します。

GUIは自動判定の状態、処理・破棄フレーム数、候補件数を表示します。タイムラインでは候補の信頼度と判定理由を確認し、利用者が確認または却下します。CLIの録画終了結果にも判定状態と件数を表示します。

実画面検証は[基本イベント自動判定 実画面チェックリスト](../visual-detection-checklist.md)に従います。画像は保存・添付せず、数値結果だけを記録します。

## 完了条件

- 開始と結果を1録画につき最大1件の候補として保存する
- ターン切り替えを同一演出から重複生成しない
- 自動候補を利用者確認なしで確定しない
- 解析遅延・例外・無効化時も録画を正常継続・停止できる
- 合成画像と偽時系列で自動テストし、実画面検証は外部チェックリストで明示実行する
