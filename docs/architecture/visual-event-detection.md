# Master Duel固有UIイベント判定

## 目的と範囲

V0.17.0ではMaster Duel日本語UIの実画面特徴から、コイントス、先攻・後攻、対戦盤面、ターン切り替え、VICTORY・LOSE・サレンダー、マッチエラー、リプレイを区別します。カード名、発動、召喚内容、ライフポイント値、フェイズ名の文字認識は対象外です。

対応表示は1920x1080のウィンドウモードと3440x1440のフルスクリーンモードです。Master Duelにボーダーレス設定はないため対応条件に含めません。日本語UI限定とし、UI変更時はローカル実動画で再評価します。

## データとプライバシー

製品の判定器はテンプレート画像や学習済みモデルを同梱しません。FFmpegから縮小BMPを受け取り、相対ROIの輝度、色、エッジ等をメモリ上で数値化して破棄します。画像、フレーム、ゲーム素材をSQLite、ログ、EXE、リポジトリへ保存しません。

実動画は利用者の端末外へ送信せず、ローカル台帳から絶対パスとイベント時刻だけを読みます。コミットできるのは、絶対パスと画像を含まない動画ID、用途、サイズ、SHA-256、評価条件です。これにより動画を公開せず、評価に使用したローカルファイルの同一性を追跡します。

## 表示プロファイル

入力全体のアスペクト比により、次の相対座標プロファイルを選択します。

- `standard`: 比率1.60から1.95。1920x1080ウィンドウを含む
- `ultrawide`: 比率2.20から2.50。3440x1440フルスクリーンを含む

解析用フレームは最大640x360に縮小します。未対応比率、空画像、破損BMPはイベントを生成しません。

## 状態機械

状態は`idle`、`matchmaking`、`coin`、`turn_order`、`active`、`overlay`、`result`、`error`、`replay`です。各イベントは許可された状態遷移と複数フレーム合意を満たす場合だけ採用します。

```text
idle -> coin -> turn_order -> active <-> overlay -> result
   \-> error
   \-> replay
```

コイントスは録画開始候補です。LP、盤面、ターンUIが安定すると対戦開始を確定します。先攻・後攻を判別できた場合は対戦記録へ保存します。カード詳細、設定画面、大型召喚、チェーン等は`overlay`として一時的に盤面が隠れた状態とし、終了イベントがない限り録画を継続します。

ターン表示は同じ表示の継続を重複候補にせず、8秒のクールダウンと手番交互性で誤検出を抑えます。結果はVICTORYまたはLOSEの特徴を優先し、理由を判別できないサレンダーは勝敗結果として扱います。勝敗を確定できない終了は`unknown`を許可します。

## 録画ライフサイクル

自動監視はコイントス等で候補録画を開始し、盤面確認前は公開履歴として確定しません。次の場合は候補を破棄して監視へ戻ります。

- マッチング失敗またはサーバーエラーを検出した
- リプレイ画面を検出した
- 45秒以内に盤面を確認できなかった

盤面確認後は録画を確定し、開始、ターン、結果の候補をSQLiteへ保存します。結果検出後は3秒の後余白を録画して停止します。ウィンドウ消失等の従来停止条件も維持します。手動録画は判定器を起動せず、開始・停止とも利用者操作だけに従います。

リプレイは自動監視の録画開始対象にしません。オフライン評価または将来の再解析では`source=replay`として開始ゲートを省略し、ターンと結果を抽出できます。

## オフライン回帰評価

ローカル台帳は動画、表示プロファイル、ライブ・リプレイ区分、期待イベントの許容時刻範囲をJSONで保持します。[台帳例](../visual-dataset-manifest.example.json)を複製してローカルパスを設定し、次を実行します。

```powershell
python scripts/evaluate_visual_dataset.py --manifest user_data/visual-dataset/manifest.json --fps 2 --markdown-out user_data/visual-dataset/report.md
```

評価器は動画を変更せず、フレームをファイルへ抽出しません。イベント種別ごとの適合率、再現率、時刻誤差、見逃し、誤検出をMarkdownへ出力します。マッチエラー後に再試行されるライブ動画は、製品の自動監視と同じく候補セッションをリセットして後続対戦を評価します。

## 完了条件

- コイントス候補と盤面確定を分離し、不成立録画を履歴へ残さない
- 一時オーバーレイで対戦終了と誤判定しない
- 開始、ターン、勝敗を重複なしの候補として保存する
- マッチエラーとリプレイをライブ対戦から分離する
- 画像資産を保持・配布せず、14本の提供動画をローカル台帳から再評価できる
- 解析失敗時も手動録画とFFmpeg録画を巻き込まない

V0.17.0のライブ監視は、判定のたびに`gdigrab`の`title=`入力を起動していました。V0.17.2では監視開始から録画終了まで1つの低解像度FFmpegを維持し、`gdigrab desktop`へMaster Duelクライアント領域の物理座標を渡します。座標は`GetClientRect`、`ClientToScreen`、Per-Monitor V2 DPI awarenessで取得します。ウィンドウが前面でなくても座標取得と判定を続けます。

## V0.17.3 実録画入力契約

2026-08-11のV0.17.2実戦3戦で、判定用`gdigrab desktop`は進行画面を取得できた一方、録画本体の`title=Master Duel`は3440x1440フルスクリーンで先頭から末尾まで同一フレームとなりました。V0.17.3ではMaster Duelの録画本体も同じ物理座標の`gdigrab desktop`へ統一します。判定用入力は1280px幅で実効約0.65fpsだったため、オフライン評価と同じ640px幅へ変更しました。640x268フレームのROI解析は実機で1枚約124ms、約8.07fpsです。

`gdigrab desktop`は座標上の最終合成画面を取得するため、別ウィンドウがMaster Duelの上へ重なると判定と録画にも映ります。現在のFFmpeg構成では、フルスクリーンの確実な録画と、重なった別アプリの除外は両立できません。

移動、リサイズ、モニター変更では判定ストリームと時間窓をリセットします。3秒間フレームが届かなければ0.5秒、1秒、2秒で3回再起動し、その後は5秒間隔で復旧を継続します。判定ストリームは最新フレーム1枚だけをメモリに保持し、録画開始後に別の判定用FFmpegを起動しません。

## FrameAnalysisと時間窓

オフライン評価とライブ監視は、状態、表示プロファイル、入力解像度、`coin/board/turn/turn_order/result/error/replay/overlay/loading`スコア、候補、合意数を持つ`FrameAnalysis`を使用します。`turn_order`はコイントスと先後表示の区別、`loading`はCONNECTING表示の右下ステータス領域との競合防止に使います。外部設定の最低信頼度0.70は維持し、次の時間窓を適用します。

- コイントス: 直近4フレーム中2件
- 盤面フォールバック・盤面確定: 直近5フレーム中3件
- 結果: 直近4フレーム中2件。盤面確定後に勝敗種別を持つ信頼度0.95以上の結果だけは1件
- マッチエラー: 直近5フレーム中3件
- リプレイ・ターン: 直近4フレーム中2件

欠落フレームと一時オーバーレイは時間窓内の不一致1件として扱い、それまでの一致を即時削除しません。候補録画はコイントス合意、またはコイントスを逃した場合の盤面3/5で開始します。盤面確定前の高信頼マッチエラー、リプレイ、45秒タイムアウトは候補と仮履歴を破棄します。リプレイは通常対戦の開始遷移で観測した最大0.761を除外するため、イベント固有閾値0.80を使用します。結果2/4または高信頼度結果1件の3秒後に停止し、次の対戦待機へ戻ります。

敗北結果は攻撃・召喚演出との競合を避けるため原則4/5フレームを必要とします。例外は信頼度0.95以上の`ultrawide-lower-loss`だけです。1920x1080の`standard-center-loss`は中央白文字の密度、横幅、中央寄せを使用しますが、単一フレーム確定を許可せず4/5を維持します。

## V0.17.4 終了境界フォールバック

V0.17.3実ログでは、録画開始から約572秒後に次戦のコイントス特徴が複数フレーム続いた一方、録画中の合意状態が`duel_start`を許可せず、前戦の録画が942.2秒まで継続しました。約594秒の`result=0.8171`はコイントス後の先後表示に対応する可能性が高く、単純な結果閾値低下は誤った勝敗保存につながります。

V0.17.4は盤面確定時刻を保持し、15秒以上経過後にコイントスが2/4で再成立した場合、`duel_start`ではなく`duel_boundary`へ正規化します。境界は勝敗を推測せず、1秒の後余白後に前戦を停止します。その後は開始監視を新しい合意状態で再開し、残っているコイントスまたは盤面フォールバックから次戦を別録画にします。初回コイントスの残像を境界へ再利用せず、信頼度0.8171の単一結果も確定しません。

## 数値診断

ライブ監視は`user_data/logs/visual-monitor/`へ数値だけのJSONを原子的に保存します。保存頻度は1秒1件、1セッション900件、最新10セッション、合計2MiBまでです。画像、BMP、ウィンドウタイトル、録画・動画パスは保存しません。GUIのフォルダーアイコンから保存場所を開けます。

## V0.23.0 イベント別解析契約

ライブ監視とオフライン評価は、同じ`VisualDetectionPipeline.analyze_frame`から`FrameAnalysis`を生成します。入力アダプターだけを座標ストリームまたは動画デコーダーへ分離し、イベント判定器と時間窓合意は共有します。

| イベント契約 | スコア | 閾値 | 合意 |
|---|---|---:|---:|
| `duel_start` | `coin_score` | 0.70 | 2/4 |
| `duel_confirmed` | `board_score` | 0.70 | 3/5 |
| `turn_change` | `turn_score` | 0.70 | 2/4 |
| `duel_result` | `result_score` | 0.70 | 2/4 |

各契約は独立してスコアと閾値到達を返します。データセット評価は表示プロファイル・イベント別にTP、FP、FN、適合率、再現率、平均絶対遅延をJSONへ原子的に保存します。全体平均だけで一部イベントの見逃しを隠しません。

利用者向けには「待機」「候補録画」「録画中」「停止」「失敗」を表示し、ROIスコア、合意数、実効fps、再起動回数は判定詳細として分離します。Windows通知は設定で無効化でき、候補開始、盤面確定、停止、失敗を重複抑止付きで通知します。通知失敗は録画処理へ伝播しません。

数値診断のZIP出力にも画像、BMP、ウィンドウタイトル、録画パスを含めません。

追跡: [V0.23.0 Milestone](https://github.com/Tao-pyth/master-duel-recorder-lite/milestone/45)、Issue #293 - #300
