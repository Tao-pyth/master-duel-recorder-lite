# 使用カード分析の設計とデータ保護

V3.0.0で追加した対象カードの候補解析を、V3.1.0では対戦の確認情報と動画の観測へ分離します。正常完了録画から候補を抽出し、明示確認でだけ使用情報へ反映します。録画なしでも対戦カード情報・初動を入力・訂正・集計できます。OCR・ジョブ・動画時刻は対戦の情報の必須条件にしません。KONAMIの画像・テンプレート・全カード辞書を配布せず、汎用PP-OCRv6 smallの日本語OCRを利用します。

## 保存と移行

schema17/18から19へ統合移行し、対戦カード正本・非使用・初動と、動画の観測・マーカー・入力を分離します。移行前に検証済み保護バックアップを作り、失敗時は開始しません。旧情報の意味・draft救済・DDL・schema検証を同じtransactionに含め、失敗時は元DBへrollbackします。confirmed表示だけを使用へ変換せず、未対応情報は原文と要確認理由を保持します。開発・配布検証は隔離fixtureを使います。[移行設計](retention-schema-3.1.0.md)を参照してください。

カードの安定ID・名称と解析対象の別名/用途/有効状態を分けます。対戦の正本は対戦ID・カードID・使用者・使用/明示非使用/不明・確認経緯・revisionを持ち、初動も対戦に所属します。解析ジョブは録画ID/世代/入力fingerprint/対象snapshot/方式版/状態/進捗を持ちます。観測は行動・名称・時刻・根拠・候補/確定/却下を動画実体と時刻基準へ関連付け、正本への根拠は任意にします。[責務境界](duel-card-information-boundary.md)を参照してください。

## 録画優先と設定

解析は既定OFF、明示ON、初期2fps、CPU1ワーカー/低優先度。正常完了後に待機ジョブへ投入し、GUI threadと録画停止処理でOCRしません。録画開始/録画中/OFF/終了で中断または待機し、所有する解析workerだけを停止します。既存結果と待機ジョブを保持し、再起動で未完了ジョブを安全に再試行します。旧設定の欠落はOFF/2fpsへ補完し、既存atomic/previous保存を維持します。

設定の許容範囲は0.25〜2fpsで、設定・Repository・workerの各境界で検証します。別プロセスの録画もOS録画lockで検知し、別のGUI/CLIが二重workerを起動しないよう解析所有lockも保持します。手動開始の準備状態、自動開始の準備状態も解析を停止する条件に含めます。

workerは途中位置と抽出器の重複抑制状態をcheckpointとして送ります。checkpointは同じジョブのmetadataへ保存し、候補テーブルには入れません。入力のfullSHA、対象snapshotのhash、方式版、fpsと復号位置を照合して途中から再開します。進捗は後退させず、正常完了したときだけ一括反映してcheckpointを除去します。初回投入はstatだけで済ませ、SHAは子プロセスが計算します。

## 認識と時刻

RapidOCR3.10.0、ONNX Runtime1.31.0、汎用PP-OCRv6 small det/recをhash固定して同梱します。小ROIはmax736、CPU/OpenCV各1スレッド、分類OFF。詳細名の表示だけは実使用を保証しません。ログの行動・空間関係・使用者の根拠と名称照合から候補を作り、判定不明を残します。

観測位置と実使用時刻は別です。過去ログを表示した時刻を正確な使用時刻へ転用しません。マーカーから根拠を確認し、必要に応じて訂正します。連続表示やログ再表示を表示系列で抑制し、同カードの再発動を名前だけで消しません。

復号はOpenCV内のFFmpegを1スレッドで実行し、独立したFFmpeg子プロセスを作りません。可変フレームレートの録画では、OpenCVの総フレーム数がduration×宣言fpsの推定になる場合があります。実フレーム数の完全一致だけで終端を判定せず、単調な実PTSと終端時刻が全長へ到達することを検証します。推定値との差、実復号数、終端誤差、実サンプル間隔をcoverageへ残し、時間未到達は失敗にします。

途中再開は保存したPTSへseekし、復号して同じPTSへ実際に到達したことを確認します。名目fps換算のframe seekだけでは保証しません。時刻seekが一致しない場合は前へ戻して再試行し、最終的には既読部分をOCRなしでgrabし、保存した物理位置とPTSを照合します。既読候補の再生成や進捗の後退を避けます。[OpenCV5.0の実装](https://github.com/opencv/opencv/blob/5.0.0/modules/videoio/src/cap_ffmpeg_impl.hpp)と固定実録画で検証しています。

## 再解析と確認

人の訂正・確定・却下は保護します。再解析は未確定自動候補だけをtransactionで入れ替え、失敗や中断で前回成功結果を失いません。入力ファイルの変化、欠損、モデル失敗を成功として扱いません。revision競合では再読込を案内します。

動画からの候補は自動確定しません。人が使用者と行動を指定して使用を確定したときだけ、明示確認の経緯とともに正本へ反映します。観測位置と実使用時刻の区別は保持します。初動は対戦側で独立したrevisionを持ちます。動画マーカーの除去・再解析・入力世代の差替えだけで、確認済み使用・非使用・初動を取り消しません。対戦情報を明示訂正するときは、使用状態と初動の整合・revisionを確認します。

## 集計

通常集計は対戦正本・初動を使い、動画なしの手入力・取込戦績も対象にします。確定戦績・既知勝敗・非hidden deck・期間・種別の条件を維持し、同じカードの複数使用を1対戦として数えます。動画削除・解析対象設定変更・再解析で確認済み集計を変えません。

候補込みの参考表示は動画側の未確認観測を利用し、母集団・不明件数と限界を示します。元動画とマーカーを削除した場合は候補参考が減り得ます。未解析・対象外・0検出・途中失敗・候補なしを非使用にしません。初動は最初に見えた対象カードから推定しません。

## 動画削除・JSON・復元

元動画の物理削除成功時に対象世代の観測・マーカー・未確認候補を除去し、対戦正本・非使用・初動を保持します。利用中入力を削除せず、遅いworker結果を削除済み・差替え済み世代へ反映しません。動画依存のcheckpointから確認済み情報を再生成しません。

管理JSONに正本・初動・動画根拠を含めますが、解析job/checkpointや実行指示は含めません。取込・復元で戻った根拠は未検証とし、現物との内容・世代・時刻基準の一致を確認してから使います。確認不可と削除済みを分け、動画不在から正本の不存在を推定しません。

## 検証と配布

探索評価の14/33名称一致やログ文字列8/8を、使用イベントのPrecision/Recallと扱いません。既存OCR・録画優先・停止応答に加え、正本の分離・移行・動画なし編集・JSON・故障回復・3EXEの回帰を確認します。認識精度の改善や全カード網羅はV3.1.0へ追加しません。上流表示とApache全文を維持し、公開assetのSHA/bytesと再取得EXEを確認する義務を[Release Contract](../release-contracts/3.1.0.md)で管理します。進捗は[ロードマップ](../roadmap.md)を参照してください。
