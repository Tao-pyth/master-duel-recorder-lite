# 最小録画

## 目的

V0.3.0では、検証済みのWindows録画環境から画面と任意の音声をFFmpegで録画し、正常停止後に非空のMKVまたはMP4として保存します。V0.4.0で自動録画補助、V0.5.0で履歴DB、V0.6.0で中断検出と非破壊修復を追加しました。

## 録画プロファイル

録画設定は `RecordingProfile` へ変換してからFFmpeg引数を構築します。

| 項目 | 既定値 | 許可範囲 |
|---|---:|---|
| フレームレート | 30fps | 1-120 |
| 解像度 | 入力元 | 幅320-7680、高さ240-4320、偶数、同時指定 |
| 映像ビットレート | 6000kbps | 500-100000 |
| 音声ビットレート | 192kbps | 32-512 |
| 映像エンコーダー | libx264 | FFmpegで利用可能なASCII識別子 |
| 音声エンコーダー | aac | 音声有効時にpreflightで確認 |
| コンテナ | MKV | MKVまたはMP4 |

設定ファイルの不足項目には既定値を補います。不正な型、範囲、片側だけの解像度指定はFFmpeg起動前に拒否します。

## FFmpeg引数

引数はシェル文字列ではなく配列として構築し、`shell=True` は使用しません。空白や日本語を含むdshow音声名も単一引数として渡します。

- 画面は `gdigrab` の設定入力を映像ストリーム0としてmapする
- Process Loopback音声は名前付きパイプの`s16le`、PC全体・入力デバイスは`dshow`を入力1として明示mapする
- 音声無効時は `-an` を指定する
- 解像度指定時はscaleフィルターを使う
- `-n` で既存ファイルの上書きを拒否する
- MP4では正常停止時にfaststart処理を行う

## 保存先

録画IDにはUUIDを使い、UTC日時と組み合わせて次の形式で保存します。

```text
user_data/data/recordings/YYYY/MM/DD/YYYYMMDDTHHMMSS_microsecondsZ_uuid.mkv
```

出力先は解決済みパスが `recordings/` 配下であること、拡張子がプロファイルと一致すること、既存ファイルがないことを開始前に再確認します。FFmpeg側でも `-n` を指定するため、確認後の競合でも上書きしません。

## 状態管理と停止

録画セッションは次の状態を持ちます。

```text
created -> starting -> recording -> stopping -> completed
                                            -> failed
```

FFmpegのstderrはバックグラウンドで読み、直近100行、1行1000文字までを診断として保持します。正常停止ではstdinへ `q` を送り、既定10秒以内に終了しない場合は強制終了して `failed` とします。終了コード0かつ出力ファイルが非空の場合だけ `completed` です。停止の再実行は同じ結果を返します。

異常終了時に部分ファイルが存在しても自動削除しません。履歴を`failed`へ確定し、失敗コード、エラー、診断情報とともにユーザーデータを保持します。

`record` と自動録画は `user_data/data/recording.lock` のOSロックを共有し、同時に複数のFFmpeg録画を開始しません。ロックファイルには録画ID、プロセスID、取得時刻だけを記録し、解放時にも監査情報としてファイルを残します。プロセス終了時にはOSがロックを解放するため、古いファイルが残っていてもそれだけで録画を拒否しません。

GUIの手動録画開始は、短時間の開始予約だけをアプリケーションサービスのロック内で行います。環境診断、Master Duelウィンドウの再取得、FFmpeg検出、録画準備はバックグラウンドスレッドかつサービスロック外で実行し、完了結果の公開時だけ再度ロックします。開始予約中は二重開始、自動監視開始、終了を明示的に拒否します。GUIはバックグラウンド操作中に同期状態取得を行わず、Tkメインスレッドの描画とWindowsメッセージ処理を継続します。

## CLI

```powershell
python -m master_duel_recorder_lite record --duration 10
python -m master_duel_recorder_lite record
```

`record` は内部でpreflightを実行し、エラーがあれば録画を開始しません。時間を省略した場合はCtrl+Cまで録画し、Ctrl+Cを受けてもFFmpegへ正常停止を要求します。

| 終了コード | 意味 |
|---:|---|
| 0 | 録画を正常に確定した |
| 2 | 設定または録画環境に問題があり開始しなかった |
| 3 | 準備、開始、停止、出力確定のいずれかに失敗した |

画面入力は現在デスクトップ全体です。録画前に通知や秘密情報が表示されていないことを確認してください。

## テスト

通常テストでは偽FFmpegプロセスを使い、開始失敗、異常終了、正常停止、停止タイムアウト、空出力、Ctrl+Cを検証します。実FFmpegではプライバシー保護のため実画面を自動取得せず、合成映像と合成音声をMKVへmuxし、両ストリームを再デコードします。

```powershell
$env:MDRL_RUN_FFMPEG_SMOKE = "1"
python -m unittest tests.test_recording_smoke -v
```
