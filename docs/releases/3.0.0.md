# V3.0.0 使用カード分析の初期実装

正常完了した録画から、登録した対象カードの表示と使用候補を抽出し、動画で確認・訂正して勝敗と関連付ける機能を追加しました。

## はじめに

1. 設定のカード分析をONにして保存します。既定はOFF、解析頻度は2fps。0.25〜2fpsで選べます。
2. 対象カードを確認し、名称・別名・用途を編集します。初期例は「増殖するG」「白き森のシルヴィ」。必要なカードだけ追加し、不要な対象は無効化できます。
3. ONの間に正常完了した手動・自動録画を後から解析します。以前の録画はレビューの「使用カード」から明示的に解析してください。
4. 対象を変えて既存録画も調べ直す場合は「再解析」を使います。作成済みジョブの対象は開始時のsnapshotで固定されます。

解析はCPU1・低優先度の子プロセスで動きます。録画開始・録画中・OFF・アプリ終了では停止して待機し、次に条件が整うと保存した途中位置から再開します。モデルの計算完了を待って録画を開始する方式ではありません。ジョブ作成時に大きな動画を読み切る処理も行いません。

## 候補をレビューする

録画履歴からレビューを開き、「使用カード」を選びます。候補を選ぶと動画の観測位置へ移動します。カードマーカーからも同じ位置を確認できます。

- 名称、対象カード、使用者、行動を確認・訂正します。「使用を確定」には使用者と行動の指定が必要です。
- 詳細表示だけから抽出した候補は使用の証拠にはしません。動画を確認して使用を確定するときだけ、使用者と行動を補ってください。
- 観測位置はログや詳細が見えた時刻です。正確な使用時刻が分かる場合は「実使用時刻」を入力します。空欄なら観測位置と区別したまま保存します。
- 使用カード候補を却下できます。人が訂正・確定・却下した内容は再解析で保護します。
- 「初動」は別に確認します。最初に検出したカードを自動的に初動にしません。
- 対象・使用者を選び、動画で未使用と確認できた場合だけ非使用を確認します。確認済み使用との矛盾は拒否し、先に非使用確認を解除するよう案内します。

他の画面で内容が変わった場合は競合を表示し、再読込してから保存します。解析進捗の更新で未保存の編集を上書きしません。

## 統計で比較する

統計の「使用カード・初動」で対象・使用者・初動カード条件を選ぶと、使用、確認済み非使用、不明の対戦数と勝敗を表示します。初動の条件も選んだ使用者へ適用します。同じカードを複数回使った対戦も1対戦です。既存の期間・対戦種別・確定戦績・正常録画・デッキ非表示の条件を維持します。

候補込みは参考表示です。確認済み使用と混ぜず、母集団と不明件数を表示します。0検出、未解析、対象外、失敗、候補のみを非使用へ置き換えません。初動未確認の対戦を、指定初動で始めた対戦へ入れません。少数の結果は勝率が大きく変動するため参考として扱います。

## CLI

ソース版のカード解析はPython3.12以上が必要です（検証環境3.13）。`python -m pip install -e ".[card-analysis]"` を追加します。配布CLI/GUIはPython・汎用モデル・依存を同梱するため、Pythonの別途インストールは不要です。

```powershell
mdrl card-analysis targets list
mdrl card-analysis targets save --name "対象名" --alias "表示上の別名" --purpose "初動"
mdrl card-analysis targets disable TARGET_ID
mdrl config set card_analysis.enabled true
mdrl config set card_analysis.fps 2
mdrl card-analysis jobs --recording-id RECORDING_ID
mdrl card-analysis analyse RECORDING_ID --timeout 1800
mdrl card-analysis analyse RECORDING_ID --reanalyse --json
mdrl card-analysis results RECORDING_ID --json
mdrl card-analysis diagnose --json
```

隔離して確認する場合は `mdrl --user-data-dir PATH ...` を使います。解析待ちが時間制限に達した場合も、ジョブと前回の成功結果を保持します。設定OFFや未完了録画は解析できません。

## 更新とデータ保護

DBはschema17から18へ専用テーブルを追加します。更新前に既存の保護バックアップを作成し、バックアップが失敗したら移行しません。移行途中の失敗はtransactionで戻します。既存録画・戦績・一般タイムラインを保持し、新しいカード情報もバックアップ・復元の検証に含めます。設定の不足キーはOFF/2fpsで補完し、既存の設定を保持します。

再解析の結果は成功時だけまとめて反映します。失敗・中断で前回の成功結果と人の編集を削除しません。途中再開は入力のSHA・対象snapshot・方式版・fpsの一致を確認し、不一致を成功扱いしません。

## 認識の限界

日本語UIのカード詳細・ログ領域を画面比率で読み取ります。画面構成、文字サイズ、隠れ、アニメーション、ログの開き方で取りこぼしや誤認識が発生します。ログ行の文字が認識できても、使用者・行動・重複の解釈が正しいとは限りません。過去ログを開いた時刻は、そのカードを使った時刻とは異なります。

固定した87名称画像の追加試験では、読める33画像の完全一致は14件でした。これはAIによる探索用参照との比較で、全動画の使用イベントのPrecision/Recallではありません。実録画・負荷の実測と未測定範囲は[検証記録](../validation/3.0.0.md)に記載します。

RapidOCR3.10.0、ONNX Runtime1.31.0、汎用PP-OCRv6 smallの検出/認識モデルをSHA固定で同梱します。KONAMIの画像・抽出テンプレート・全カード辞書は含めません。上流の著作権表示、モデル出所、Apache全文は同梱ライセンスに記載しています。

対象限定の初期実装です。全カード網羅認識、効果適用の自動確定、改善手の自動提案は対象外です。[Release Contract](../release-contracts/3.0.0.md)、[設計と保護](../architecture/card-analysis.md)、Issue #665〜#671、Milestone V3.0.0で追跡します。
