# V1.4.3: アプリ内自動更新updater化

V1.4.3では、V1.4.1/V1.4.2で確認されたアプリ内更新後のPyInstaller展開失敗に対して、手動更新へ逃げずに自動更新導線を作り直します。旧GUIプロセス自身やPowerShellの自己置換に依存せず、GUIに同梱した専用updater EXEが終了後の置換、検証、ロールバック、再起動を担当します。

## 対象Issue

- #459: リリースツールの固定バージョン期待値を恒久的に解消する
- #460: バージョン・文書・検証記録を整合する
- #461: release toolingテストの現在版期待値をプロジェクト版から導出する
- #462: アプリ内更新を専用updater方式へ切り替え自動更新を維持する
- #463: 専用updaterで現在EXEを安全に自動更新する
- #464: V1.4.1/V1.4.2更新失敗と旧版更新コードの限界を検証記録へ残す
- #465: 自動更新を再導入するためのlauncher/installer/side-by-side方針を設計する

## 変更内容

- `master-duel-recorder-lite-updater.exe`を配布物として追加し、GUI EXEへ同梱
- GUIの更新適用処理をPowerShell自己置換から専用updater起動へ変更
- updaterで親GUI終了待機、候補SHA-256再確認、staging、`.previous`退避、置換後GUIスモーク、失敗時ロールバック、成功時再起動を実施
- release workflowでCLI/GUI/updaterの3 EXEとSHA-256を公開し、公開済みassetを再ダウンロードして3 EXEをスモーク
- release toolingテストの固定バージョン期待値をプロジェクト版から導出
- Windows Credential ManagerのCredentialBlobがUTF-16で返る場合もYouTube token JSONを読めるように維持

- `python scripts\verify_release_tag.py v1.4.3`
- `python scripts\build_windows_exe.py --require-youtube-oauth-client`
