# V3.1.0 元動画の保存管理と対戦カード情報の分離

元動画の保存管理と、動画がなくても使える対戦カード情報の操作説明です。正式公開・配布確認の状態は[GitHub Release](https://github.com/Tao-pyth/master-duel-recorder-lite/releases/tag/v3.1.0)、[親Issue #672](https://github.com/Tao-pyth/master-duel-recorder-lite/issues/672)と対応するAct記録を正本とします。[検証記録](../validation/3.1.0.md)も参照してください。

## 保存容量・期限を設定する

設定の「録画設定」で「動画の保存最大容量」「動画の保存期限」を入力し、設定を保存します。容量はGiB、期限は日数の非負整数です。初期値0は無制限です。1GiBは1,073,741,824bytes、1日は24時間として扱います。

保存した容量・期限は次の通常GUI起動で確認します。起動中の進捗を表示し、移行と未完了削除の回復、期限超過の整理、容量超過の整理、投稿後削除の再試行の順に進めます。設定の保存、診断、バックアップ復元だけで新しい整理を開始しません。

期限は録画開始日時、欠落時は作成日時から判断します。ちょうど指定日数になった動画は残し、それより古い登録済み元動画を対象にします。容量は期限整理後に再計算し、古い元動画から上限内になるまで整理します。画面に表示される件数にかかわらず全履歴を確認します。

容量計算はrecordings領域内の実ファイルを対象とし、保護・未登録・削除中の退避ファイルも含みます。自動削除は登録済み元動画だけです。投稿用MP4、クリップ、プリロール、未登録動画は自動削除しません。この設定は端末全体の空き容量上限ではなく、常時整理も行いません。

## 残す動画を保護する

戦績管理で録画のある行を選び、「自動削除から保護」を付けます。戦績が未入力でも設定できます。容量・期限・投稿後の自動削除から除外します。

保護対象を手動で削除すると追加警告を表示します。継続の確認はその操作だけに適用し、保護設定を解除しません。キャンセルすれば動画と管理情報を保持します。

## 二つの削除を使い分ける

選択行の「その他」から操作します。

| 操作 | 削除するもの | 残すもの |
| --- | --- | --- |
| 動画だけ削除 | 元動画、その動画の一般・カードマーカー、未確認候補 | 録画履歴・戦績・タグ・メモ・確認したカード情報・初動・投稿URL・投稿用MP4・クリップ |
| 戦績・録画履歴ごと削除 | 対象の元動画、録画履歴・戦績と所属するカード情報・初動・マーカー・ローカル投稿情報等 | 共通カード設定、他の対戦、YouTube上の投稿、投稿用MP4・クリップ |

自動整理には「動画だけ削除」と同じ保持規則を使います。実行中の録画・準備・解析・レビューで使用する動画、安全を確認できない動画は削除を見送ります。削除理由・日時と、投稿後削除の再試行待ちは選択行の動画状態へ表示します。

DB・設定のバックアップに動画本体は含まれません。削除した動画を戻したい場合は、削除前に別の場所へ自分で保存しておく必要があります。途中のDB障害は次の通常起動で削除状態・理由を回復しますが、物理削除後の動画復元は保証しません。

## YouTube投稿後の自動削除

設定の「YouTube」で「YouTubeアップロード後、動画の自動削除を行う」を選び、設定を保存します。初期状態は非選択です。投稿終了後の保存済み設定で判断するため、未保存のチェック状態は適用しません。

YouTubeが送信を受領し、動画ID・URLと成功結果をDBへ保存できた後、実際に送信したMP4、準備記録、元動画が対応することを確認して元動画を削除します。YouTube側の変換処理や再生・公開の完了を待つ設定ではありません。投稿用MP4は残ります。

元動画が保護・使用中、設定OFF、内容不一致、出自不明、バックアップ保持不能の場合は削除しません。削除失敗でも成功済みURLを保持します。元動画がなくても、有効な準備済みMP4があれば既存の初回投稿・再試行を利用できます。

一時的な見送りを保存した要求だけ、次の通常GUI起動で再確認します。その時点の設定・保護・利用・動画内容を確認し直します。過去の成功投稿をまとめて遡って削除したり、JSONに含まれた投稿URLから削除要求を作ったりしません。

投稿中に終了操作をした場合は、投稿と動画削除の後処理が成功・見送り・失敗のいずれかで終わるまで待ちます。処理中は新規操作を抑え、画面の更新を続けます。

## 動画なしで使用カード・初動を管理する

戦績管理で対戦を選び、「その他 → 使用カード・初動」を開きます。カード名・使用者・確認状態を選び、「カード情報を保存」で入力・訂正します。使用を確認したカードは、使用者ごとの初動として確認できます。録画なしの手入力・取込戦績も同じ画面で扱います。

使用・明示非使用・不明・初動は対戦の情報として保持します。動画の削除、再解析、解析対象の無効化で人が確認した情報を消しません。確認済み統計も維持します。動画側の未確認候補を消すと「候補込み」の参考集計は減る場合があります。候補がないことは未使用の確認ではありません。

## 更新・JSON取込・バックアップ復元

旧DBのschema17/18は、検証済み保護バックアップを作ってschema19へ移行します。移行失敗時は元DBを保持します。確認済みカード情報がある録画に戦績がなければ、情報の所属先として下書き戦績を1件作ります。勝敗・先後・コインは不明のままにし、入力を推測しません。自動対応できない旧情報は要確認として保持します。

管理データJSONは確認したカード情報・初動・完了投稿URL・動画ID・一般/カードマーカー・確定削除理由/日時・保護を含みます。旧形式も受け入れ、欠落したカード情報を未使用などへ補完しません。動画・MP4・OAuth・送信待ち・解析ジョブ/途中位置・未完了削除・投稿後再試行要求は含めません。

JSON取込は現在の管理データの置換です。事前バックアップと確認後に適用し、対象の関連情報も整合させます。履歴・全体の初期化では対象のカード情報等も消します。自由記述タグだけの初期化で対戦カード情報は消しません。JSON取込・初期化は動画本体を削除しません。残った未登録動画は自動整理されません。

復元はDB・設定をバックアップ時点へ戻す操作です。動画は戻りません。成功後に保存設定・保護表示・未保存編集の基準を再読込します。戻ったマーカーは動画内容・時刻基準の一致を確認してから利用します。古い解析・投稿・削除処理を復元直後に自動実行しません。

| 復元後の表示 | 意味 |
| --- | --- |
| 削除済み・保存済みの理由 | バックアップ内に確定削除の記録がある |
| 復元時削除済み | 保存先を確認でき、対象動画がない。元の削除原因は不明。表示日時は復元時の確認日時 |
| 確認不可 | 保存先未接続・権限不足などで現物を確認できない。削除済みとは断定しない |

バックアップ後に行った編集・後発の削除理由は、古いバックアップの復元では戻りません。

## 容量が減らない・削除を見送る場合

保護・未登録・使用中の動画が多いと、容量上限を達成できない場合があります。表示された理由を確認し、プレイヤーや処理を終了してから通常GUIを再起動してください。必要な動画の保護を維持する場合は上限も見直します。

空き容量不足やバックアップ保持枠の不足では、安全な事前バックアップを確保できず動画削除を見送ります。先に不要な別データを片付ける、必要なファイルを別ドライブへ保存するなどして空きを確保します。保護バックアップは自動整理されません。不要な世代を整理する場合はアプリを終了し、必要なバックアップを別の場所へ保管してから行い、通常GUIを再起動します。

未完了削除が残った場合は、設定・診断で状態を確認し、次の通常GUI起動で回復してください。動画操作と管理データ置換は回復完了まで制限します。ロックや削除途中の退避ファイルを手で消す対処は行いません。
