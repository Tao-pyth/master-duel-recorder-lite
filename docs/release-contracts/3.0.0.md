# V3.0.0 Release Contract

## Decision

ユーザーの2026-10-14の連続実行依頼に基づき、使用カード分析の初期実装をV3.0.0へまとめる。Issue/Milestone登録、確定Scopeの実装、commit/main反映/push/tag/正式Release/公開asset検証/closureまで許可済み。追加Observeの固定モデル試験に基づくOrient006の方向を採用する。既存AGENTS.mdのユーザー編集と独立#629を保持する。

## Release Goal

正常完了した録画から対象カードの使用候補を自動解析し、時刻付きレビューで確認・訂正し、カード使用と初動を勝敗へ関連付けて分析できる。未認識を未使用へ混ぜず、再解析や録画開始で既存データを失わない。

## Target Version

baseline v2.7.21、target_version v3.0.0。ユーザーが初期実装をこの版へまとめるよう指定。main/HEAD/正式Release/tag実commitは1f6b7fa2a6d1cca390fed72c93e5e9bec841d568で一致。2つのversion metadata、release-notesも2.7.21。通常Fix更新ではなくユーザー指定のメジャー更新を行う。

## Scope

1. schema18の追加専用テーブルで、対象カード/別名/用途/有効状態、解析ジョブと世代/入力fingerprint/対象snapshot/進捗、カード観測と確認状態、確認済み非使用、初動確認を構造化保存する。一般duel_eventsや戦績を再設計しない。
2. RapidOCR3.10.0＋ONNX Runtime1.31.0 CPU、PP-OCRv6 small det/recを使用。汎用モデルをhash固定でCLI/GUI EXEへ同梱。CPU intra/inter/OpenCVを各1、det max736、分類OFF。録画内のカード詳細/ログ領域を画面サイズに対する比率で処理し、利用者の対象名/別名に照合する。
3. 行動を伴うログから名称・使用者・発動/通常召喚/特殊召喚/不明・観測時刻・根拠を候補抽出する。詳細表示だけと使用の根拠を区別。表示系列/行内容/前後関係で重複を抑制するが、同カードの別の使用を消さない。実使用時刻は観測時刻と区別し、確認・訂正する。
4. application所有の解析管理と独立した低優先ワーカー1本。手動停止成功・自然終了・自動録画stoppedの3経路から正常完了録画だけを投入。設定は既定OFF、明示ON、初期2fps（上限内の検証付き）。録画開始/録画中/OFF/終了で解析を中断または待機し、後で再開/再試行。再起動時のrunningは安全に待機へ戻す。
5. 対象カードプリセット（ユーザー例の短い名称設定と用途ラベルのみ）、追加/編集/別名/無効化。モデル/公式全カード辞書や画像を追加する方式ではない。レビューに状態/解析/再解析、候補一覧、名称・使用者・行動・時刻・初動の訂正、確定/却下、明示的な非使用確認を追加。カード観測を既存seek/視覚timelineへ投影する。
6. 統計に使用カードと初動の集計を追加。既存の確定戦績/既知勝敗/正常録画/非hidden deckと期間・対戦種別条件を維持。対象カード・使用者・初動カード条件から1対戦単位で使用/非使用/不明と勝敗を比較。候補込みは参考表示として明確に分け、確認済み母集団へ混ぜない。
7. CLIで対象/ジョブ/解析結果の確認と隔離領域での明示解析を提供し、配布worker起動・診断を検証できるようにする。既存CLI/GUI操作の互換を維持。
8. 設計・操作・移行/失敗復元・認識限界・検証文書、version/release-notes/roadmap、正式Releaseと3EXE/7asset検証、対象Issue/Milestone closure。

## Non-Scope

全カード網羅認識、プレイ改善手の自動提案、効果適用の自動確定、クラウドへの録画送信、OBS依存、録画中リアルタイム解析、KONAMIの画像/抽出テンプレート/全カードデータ配布、既存録画/DB/キュー/資格情報の削除・初期化、YouTube仕様変更、#629の実利用フィードバック収集。

## Chosen Approach

- データ責務をcard_analysis_repositoryとモデルへ分け、既存protected backup/transaction migrationを拡張する。移行前backupが失敗したら移行しない。移行失敗はrollbackし、既存schemaと行を維持する。バックアップ/復元検証には追加テーブルの件数も含める。
- 自動観測はcandidate。OCRconfidenceを使用確率へ転用せず、ログ表示位置にはその時刻意味を表示する。人の訂正/確定/却下は保護し、再解析失敗・中断で前回成功結果を失わない。完了結果の入替はtransactionで行う。
- jobは対象snapshotと解析方式版、入力のサイズ/mtime/hashを持つ。正常完了していない録画、録画中ソース、対象なし、欠損/変更ソースは成功にしない。同録画の二重実行はしない。
- 解析子プロセス/workerを停止できるようにし、録画開始をOCR完了待ちにしない。開始時の短い競合も低優先度・1ワーカー・停止要求で制御。GUI threadでモデル推論しない。停止/終了の処理は所有する解析プロセスだけを対象にする。
- 未解析/対象外/識別不能/途中失敗と確認済み非使用を別にする。初動は候補から人が確認する。確認済みの初動と、最初に検出されたカードを混同しない。確認済み比較と候補込みの参考比較に母集団/不明件数を表示。
- 非秘密設定にON/OFFとfpsを追加し、旧設定の欠落はOFF/2fpsへ補完。対象はDBへ保存。既存atomic/previous保護と未保存設定のUXを維持する。
- 汎用モデルのSHAをbuild時とruntime診断で検証し、Apache全文と上流表示/出所を同梱。モデルはPython packageの汎用資産から取得し、ゲームEvidenceをrepoやReleaseへ入れない。

## Acceptance Criteria

- [ ] AC1 データ: 旧schema17から18へ、既存録画/戦績/timeline/設定を保持して移行できる。移行前backup、backup失敗時非移行、migration失敗rollback、復元後データ保持を隔離fixture/コピーで実証。
- [ ] AC2 対象: プリセットが使え、任意の名称/別名/用途の追加・編集・無効化・再表示ができる。空名/重複正規化名/不正値を拒否し、旧jobの対象snapshotを後編集で変えない。
- [ ] AC3 自動解析: 実録画からOCRと対象照合を実行し、名称/使用者/行動/観測時刻/根拠を構造化候補として保存する。名称表示だけ、行動なし、判定不明を使用確定にしない。原録画不変を確認。
- [ ] AC4 時刻/重複: 連続表示/過去ログ再表示の重複を抑制し、同カードの異なる再使用を保持。観測/実使用時刻と根拠を区別。ROI/frame時刻が動画時間へ対応し、根拠位置へseekできる。全使用時刻の正確性を保証する表示をしない。
- [ ] AC5 ジョブ: queued/running/completed/failed/中断待機と進捗を保持し、同録画二重実行なし。再起動後の安全な再試行、欠損/変更ソース、OCR/外部処理失敗を成功にしない。未完了結果と前回成功結果を混ぜない。
- [ ] AC6 録画優先/OFF: 自動投入が3完了経路へ接続。OFF時は投入/実行しない。録画開始要求で解析停止を要求し、開始処理をモデル推論の完了待ちにしない。録画中は新しい解析を走らせず、OFF/終了で所有workerを終了できる。取消や終了で原録画/既存結果を削除しない。
- [ ] AC7 訂正保護: 名称/使用者/行動/時刻/初動を保存・再表示でき、確定/却下を維持。revision競合で後から上書きしない。再解析成功・失敗・中断・対象変更でも訂正/確定/却下を保持する。
- [ ] AC8 GUI: 通常Windows GUIで設定・対象管理・解析状態/再解析・候補確認/訂正・初動/非使用確認・マーカーseekへ到達できる。対象不在/失敗/空結果/処理中/終了の状態が分かり、二重操作と未保存誤破棄を防ぐ。日本語100/150/200%相当、小画面で主要操作が到達可能。
- [ ] AC9 集計: 1対戦単位でカード使用/確認済み非使用/不明と勝敗、初動別勝敗、初動カード条件下のカード使用比較が正しい。確定戦績/期間/種別/hidden/正常録画を維持。イベントの重複で対戦数を増やさず、未解析/対象外/候補のみ/失敗/初動不明を非使用にしない。候補込みの参考表示は分母と不明件数を区別。
- [ ] AC10 CLI/API: 隔離データ領域で対象・job・結果を操作/確認でき、GUIと同じ保護を使う。解析worker起動とエラー分類が配布形態でも実行できる。既存コマンドを維持。
- [ ] AC11 認識/負荷検証: 固定87ROI/5ログの追加評価を基準に、少なくとも保存済み実録画3本で全パイプラインを検証し、候補/判定不明/取りこぼし/重複/時刻意味と処理時間/CPU/メモリを記録。未解析の範囲を検出なしにしない。CPU1ワーカーと録画開始時の停止応答を実証。隔離した録画負荷試験で録画中に解析が実行されず、録画出力が正常なことを確認。実ゲームFPSや全イベントPrecision/Recallを未測定なら明記。
- [ ] AC12 配布: det SHA090f04... とrec SHA6f3272... の汎用PP-OCRv6 smallをhash固定で同梱し、CLI/GUI EXEの実推論/モデル診断がネット接続なしで動く。モデル欠損/不整合は成功にしない。上流著作権/Apache全文/モデル出所を同梱し、KONAMIの素材を含まない。
- [ ] AC13 回帰/文書: 重点テスト、Ruff、ResourceWarningをエラー扱いした全unittest、Windows実widget/実動画、3EXE build/smokeが合格。設計、移行、操作、認識限界、検証、README、roadmap、release-notes、2つのversionが3.0.0で一致。
- [ ] RC1 commit/main/push: 対象だけを英語commit＋初心者向け日本語本文でcommit。既存のmain直接公開運用へ通常fast-forward反映/pushし、ユーザーAGENTS編集を含めない。main CI成功を確認。
- [ ] RC2 tag/公開: 同一公開commitへv3.0.0タグ、Windows Release CIがtest/build/3EXE smoke/公開検証に成功。latest v3.0.0、draft/prerelease=false、3EXE+3SHA+集約SHAの7assetを公開。
- [ ] RC3 配布確認/closure: 7assetのbytes/SHA/集約SHA、再取得3EXE smokeとOCR診断/実推論、2.7.21から3.0.0への更新候補を確認。対象Issue/Milestoneを証拠付きcloseし、Obsidian Actと次baseline入口を記録。ユーザー指定終了境界でgoal完了。

## Rejected Alternatives

手動入力だけへの縮小、文字列8/8をイベント抽出8/8とする保証、Windows OCRの未パッケージEXEでの正式サポート推定、min736で小ROIを大きく拡大、録画中の常時解析、一般timelineのラベルだけへ埋める保存、0検出＝未使用、最初に見えた対象＝初動、失敗時の既存結果削除、KONAMI素材同梱は採らない。

## Risks

低精度と空間行解釈は実録画で測定し、候補訂正を提供するだけでAC3/4/11を達成扱いにしない。process/FFmpeg/DLLの停止漏れ、モデル/パッケージ差、バックアップ/復元、GUIサイズ、条件付き集計を重点検証。新しい重要事実が方向を崩す場合はObserve/Orient/Decideへ戻して契約を明示更新する。

## Deferred Solution Queue Intake

全カード網羅抽出はKeep。対象限定の使用分析を実装するが、網羅候補の完了扱いにはしない。既存の長時間録画/clip/シーズン残部は本件と独立してKeep。新規の曖昧なqueue項目は作らない。
