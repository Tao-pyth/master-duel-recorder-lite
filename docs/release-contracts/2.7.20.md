# V2.7.20 Release Contract

## Release Goal / Target Version
YouTube認証失敗からGUIで復旧でき、相手デッキ×自分デッキごとの勝率を確認できる。
baseline: v2.7.19 / target: v2.7.20。既存のYouTube連携・戦績統計の改善なのでFix更新。

## Scope / Tracking
- [#658](https://github.com/Tao-pyth/master-duel-recorder-lite/issues/658): OAuth invalid_grantの誤分類修正とPySide6再連携の実装。
- [#659](https://github.com/Tao-pyth/master-duel-recorder-lite/issues/659): 既存記録から相手×自分デッキ集計と統計内タブ追加。

- Milestone [V2.7.20](https://github.com/Tao-pyth/master-duel-recorder-lite/milestone/102)、label version:2.7.20。

## Chosen Approach
OAuth文字列errorとYouTube APIの辞書errorを区別し、invalid_grantをreauthorizeへ分類する。一般HTTP400は入力失敗の分類を維持。再認証が必要な失敗を自動再試行せず、設定→YouTube→連携するの案内へ接続する。
既存ApplicationService.connect_youtubeをGUIのバックグラウンド処理へ接続し、認証中の多重実行・競合操作を防ぎ、成功・失敗いずれもボタン状態を復元する。接続状態は資格情報の存在確認を有効性検証と誤認させない文言にする。
StatisticsRowへ既存相手デッキを読み取り、条件適用後の母集団を両デッキ名のタプルで集計する。専用集計型は両デッキを別項目で持ち、Dashboardは末尾既定値で旧constructor互換を保つ。GUIの「デッキ相性」タブに相手/自分/対戦/勝/負/引分/自分勝率を表示する。

## Acceptance Criteria
- AC1: HTTP400 invalid_grantはreauthorizeと日本語の再連携案内。一般400・401・403 quota/権限・5xx分類と診断伏せ字を維持。
- AC2: 再認証が必要な失敗は1回で止まり、実行前の録画・MP4・資格情報を保持。隔離fake連携の回復後に投稿が成功し、投稿済み重複を拒否。
- AC3: GUI連携ボタンが実サービスを非同期で呼ぶ。認証待ち中の二重開始/切断を防ぎ、成功/例外/開始失敗で状態復元。結果を設定画面へ表示。
- AC4: 相手×自分の組合せを別々に集計し、両値の未設定と正規化、区切り記号を含む名称を正しく扱う。
- AC5: 確定/勝敗入力済み、正常完了録画または手入力/取込、非表示自分デッキ除外の既存規則を保つ。勝率=勝利/(勝+負+引分)。
- AC6: 統計内タブに相手/自分の別列と対戦/勝敗/引分/自分勝率。期間×対戦種別、解除、空状態を反映。全体カードは従来どおり全件。
- AC7: 980px相当でも新タブへ到達でき、長い名前はツールチップ/横スクロール等で読める。実widgetと日本語画面の確認。
- AC8: 関連テスト、全unittest（ResourceWarningをエラー扱い）、Ruff、版一致、3EXE build/smokeが合格。README/設計/ユーザー文書/変更履歴/検証記録を一致させる。

## Test Requirements
HTTP合成応答による分類/伏せ字、再試行停止と失敗時データ保護、fake再連携後投稿/重複防止、GUI実ボタンの非同期呼出/二重操作/結果復元、両デッキ集計と母集団/条件/正規化/未設定、全タブの期間/種別回帰、空状態、画面確認。
既存CIと同じRuff、全unittestをローカルで実行。3EXEの配布形式と隔離smokeを検証する。

## Non-Scope / Rejected Alternatives
実Googleログイン同意の代行・実動画投稿、実行時データ/資格情報の削除や書換、DB/設定schema変更、400全般の再認証化、統計全体の再設計、新機能の範囲拡張は対象外。
2026-10-10の追加依頼「コードの反映と正式Releaseの公開を行ってください」により、正式公開までを対象とする。実装とAC1-8は変更せず、以下の公開責務を追加する。
