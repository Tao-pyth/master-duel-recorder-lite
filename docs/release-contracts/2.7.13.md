# V2.7.13 Release Contract

## Release Goal
採用1案の左一覧・右編集をデッキ名/タグ/シーズンへ統一し、既存機能を安全に操作できる。
## Target Version
v2.7.13（既存UI改善のFix）。baseline v2.7.12。
## Scope / Chosen Approach
専用Qt管理widgetによる共通構成。左検索・フィルター・新規・一覧、右対象名・フォーム・保存/取消と削除またはアーカイブ/レポート。既存service経由CRUD。識別子固定、dirty snapshot、空/新規/既存を分離。
## Non-Scope
全ナビ刷新、戦績管理の別フィードバック、録画/DB/設定/CLI/API変更、実データ編集、#629。
## Acceptance Criteria
- AC1: 3ページすべて採用1案の左右構成。980x640/1180x760/1440x1024、150/200%相当で主要操作到達可能。右側縦スクロールと幅調整。
- AC2: 名前/説明検索、用途（デッキ/タグ）・状態（シーズン）フィルター、件数/0件表示。新規で空フォーム、保存で追加、既存を保存すると更新。
- AC3: デッキ全フィールド/タグ全フィールド、色、使用回数、独立した用途/表示、シーズン全フィールドとreport_notes保持。削除確認、アーカイブ確認、レポート/HTML導線維持。
- AC4: 行/検索/フィルター/新規/他ページ/終了で保存・破棄・取消。取消/保存失敗は入力と選択を保持。背景refreshでdirty入力を消さない。保存後対象と一覧を整合。
- AC5: 隔離データの実widget CRUD/取消/エラー/検索/遷移回帰、全unittestとRuff、通常日本語GUI画像、3EXE build/smoke、公開7asset/hash/再取得3EXEsmoke、Issue/Milestone closure。
## Rejected Alternatives
他2案と既存上部フォーム維持。全面的サービス書き換え。
## Risks
狭い画面と未保存入力の状態遷移。Qt専用共通widgetに限定して保守性を保つ。
## Deferred Solution Queue Intake
Keep: 既存全件。今回独立要件に混入しない。
## Implementation Handoff
W1: 3ページ共通左右構成・新規/編集・検索/状態・既存操作接続。背景は上部フォーム混在解消。AC1-3。依存なし。
W2: 未保存保護・失敗/背景refresh・回帰検証。AC4、W1依存。サービス形式変更はしない。
W3: 画像/全テスト・文書・配布公開と検証。AC5、W1/W2依存。
各作業は独立Issue登録後実装。テスト要件は各ACに対応。既存継続外部操作承認を継承。
## Release Contract
required: Implementation, Tests, UI, README, Architecture Docs, User Docs, CHANGELOG, Version Metadata, Commit, Push, Tag, Build, CI, Packaging, GitHub Release, Artifact Publish, Published Verification, Release Notes, Backward Compatibility, Issue/Milestone closure。
not-required: Database, Database Migration, Configuration, Configuration Migration, API, CLI, PR（既存mainへfast-forward merge）。
needs-investigation: なし。
公開証拠はv2.7.13 main/tag SHA一致、Main/Release CI success、7assets検証、再取得3EXEsmoke。
