# V2.6.0 Release Contract

## Release Goal

自動録画の開始判定が揃う前の短い映像を、利用者が明示的に有効化した場合だけ録画へ含められるようにする。初回版は「自動録画限定・短秒数・上限付き」のプリロールMVPとし、長時間バックグラウンド録画や任意クリップ保存には広げない。

## Scope

- 自動録画中だけ有効なプリロールバッファを追加する。
- プリロールは既定無効とし、設定で明示的に有効化する。
- プリロール秒数と一時保存上限を検証付き設定として扱う。
- 一時ファイルは `user_data/` 配下に置き、容量または時間の上限で保持する。
- 自動録画が確定した場合、保持済みの短い直前映像を録画ファイルへ含める。
- `duel_start` の録画内位置は、プリロールを含む録画ファイル先頭からの経過として扱う。
- プリロール失敗時も本録画、履歴DB、既存録画ファイルを破壊せず、診断情報を残す。

## Non-Scope

- 手動録画へのプリロール適用。
- 長時間バックグラウンド録画。
- ShadowPlay/Steam相当の任意クリップ保存。
- 常時保存履歴、バックグラウンド録画一覧、録画後の高度レビュー強化。
- OBS Plugin、OBS WebSocket連携。
- 直接アップロード、OAuth連携。
- DB schema変更。

## Acceptance Gate

- 既存設定ファイルを読み込んだ場合、プリロールは既定無効で補完され、既存の自動録画動作は変わらない。
- 利用者がプリロールを有効化し、秒数と上限が妥当な場合だけ、自動録画開始時に短い直前映像が録画へ含まれる。
- プリロール秒数、保存上限、無効/有効状態はCLIとPySide6設定画面から確認・変更できる。
- 不正なプリロール秒数や保存上限は設定保存時に拒否される。
- 一時バッファは `user_data/` 配下に保存され、上限を超えて増え続けない。
- プリロールバッファまたは結合に失敗しても、通常の自動録画は可能な範囲で継続し、失敗理由が診断へ残る。
- `duel_start` は、プリロールを含む録画ファイル先頭からの経過として保存される。
- 手動録画、直接アップロード、OAuth、DB schema、既存録画ファイル、queue、manifestを変更しない。
- Ruff、対象単体テスト、GUI smoke、CLI/GUI/updater EXE build、CI、公開Release asset検証、ダウンロード後EXE smokeに合格する。
