# Release Contract 2.7.7

## Summary

V2.7.7 adds automatic duel-record defaults for auto-watch recordings. Users can choose their own deck, season, and desired play order before starting auto-watch; successful auto-watch recordings use those values when creating a new draft duel record. This release keeps recording, detection, database schema, queue, manifest, and OAuth storage boundaries intact.

## Scope

- Add auto-watch duel default controls to the PySide6 recording page:
  - own deck
  - season
  - desired play order
- Snapshot the selected defaults when auto-watch starts.
- Keep the snapshot fixed for the running auto-watch session; UI changes after start do not affect that session.
- Apply the snapshot only to successful auto-watch recordings that create a new draft duel record.
- Preserve detected `result` and detected `play_order` as higher-priority values than user defaults.
- If desired play order and detected actual play order are both known, set `coin_face=heads` when they match and `coin_face=tails` when they differ.
- Do not infer `coin_face` when detected `play_order` is `unknown`.
- Store auto-watch defaults as non-secret configuration with safe defaults for older `app.toml` files.
- Explain in UI and docs that this `coin_face` value is based on desired-vs-actual play order comparison, not direct coin-toss image recognition.
- Add or update tests for config loading/saving, service snapshot behavior, draft application, GUI contract, and existing watch regressions.
- Update README or architecture docs, release notes, validation notes, version metadata, and OODA Act evidence for V2.7.7.
- Create GitHub tracking Issue/Milestone before implementation, subject to external mutation approval.

## Non-Scope

- No SQLite schema migration.
- No runtime data deletion, overwrite, or initialization.
- No recording file, FFmpeg command, capture target, queue, manifest, OAuth, or YouTube upload behavior changes.
- No direct coin-toss image recognition.
- No new `desired_play_order` duel-record database column.
- No dedicated desired-play-order statistics.
- No application of these defaults to manual recordings or manual no-recording duel records.
- No modal duel input at auto-watch recording completion.
- No long-running background recording or arbitrary clip-save feature.
- No marker-to-YouTube-description timestamp export.
- No OBS Plugin or OBS WebSocket dependency.
- No V2.8.0 or later version bump.

## Acceptance Criteria

- The PySide6 recording page lets the user choose auto-watch defaults for own deck, season, and desired play order.
- Starting auto-watch captures the current defaults as a fixed snapshot for that watch session.
- Changing the UI after auto-watch starts does not affect already running auto-watch recordings.
- A successful auto-watch recording that creates a new draft duel record receives the selected own deck and season defaults.
- Candidate-discarded recordings, failed recordings, manual recordings, manual no-recording duel records, and existing duel records are not changed by auto-watch defaults.
- Detected `play_order` remains authoritative over any default.
- `coin_face` is auto-filled as `heads` only when desired play order matches detected actual play order, and `tails` only when they differ.
- `coin_face` remains `unknown` when actual `play_order` is `unknown`.
- Older config files without the new keys continue to load with unset defaults.
- Existing recording start/stop, auto-watch start/stop, preroll, visual detection, history, timeline, upload, and data protection tests remain passing.
- Public GitHub Release artifacts download and verify as V2.7.7 after release.
