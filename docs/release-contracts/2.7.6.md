# Release Contract 2.7.6

## Summary

V2.7.6 fixes the battle history table refresh after duel registration from the review screen. It keeps the V2.7.x hotfix line and does not change database, configuration, recording, or upload behavior.

## Scope

- Refresh the battle history table after a successful duel save from the review screen's `戦績入力` tab.
- Add a narrow optional save callback to `create_review_window()` or an equivalent parent-notification path.
- Pass the refresh callback from PySide6 history actions that open the review screen.
- Call the refresh path only after `save_duel_record` or `update_duel_record` succeeds.
- Preserve current battle history filters by reusing the existing history refresh query path.
- Keep the existing standard duel editor refresh behavior.
- Add or update GUI contract/regression tests for the review-save-to-history-refresh behavior.
- Update release notes, validation notes, version metadata, and OODA Act evidence for V2.7.6.

## Non-Scope

- No SQLite schema migration.
- No configuration schema migration.
- No recording command, FFmpeg command, or output path changes.
- No runtime data deletion or initialization.
- No OAuth, queue, manifest, direct upload, or YouTube workflow changes.
- No generic service-layer event bus.
- No realtime synchronization across every open review/statistics window.
- No forced display of records that do not match the current battle history filters.
- No V2.8.0 or later version bump.

## Required Evidence

- Focused GUI contract or regression test proving review-screen duel save can notify the parent battle history table refresh.
- Regression check that save failure does not trigger the parent refresh callback.
- Existing GUI contract tests remain passing.
- Full pytest or a justified focused test set plus full test status.
- Ruff.
- Version metadata updated to `2.7.6`.
- Release notes and validation notes updated.
- For formal release: commit, push, tag, CI, Windows EXE build, GitHub Release, artifact publication, published verification, and Issue #612 closure or explicit closure deferral.

## Acceptance Criteria

- Saving a duel record from the review screen's `戦績入力` tab refreshes the parent battle history table without pressing `更新`.
- The refresh happens only after a successful save.
- Save failure keeps the existing error behavior and does not make the parent table appear updated.
- Existing battle history filters continue to determine which rows are displayed after refresh.
- Standard no-recording/manual duel editor behavior remains unchanged.
- Battle history table fixed row height and existing display contract remain intact.
- Public GitHub Release artifacts download and verify as V2.7.6 after release.
