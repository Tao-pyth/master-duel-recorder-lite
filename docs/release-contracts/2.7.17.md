# V2.7.17 Release Contract

## Decision / Release Goal
自動監視開始時に選んだ対戦種別を新しい戦績下書きへ入力できる。
## Target Version
baseline v2.7.16、target_version v2.7.17。既存初期値の拡張でFix更新。
## Scope
録画画面の対戦種別combo、AppConfig読込/検証/保存/更新キー、AutoWatchDuelDefaults snapshotとdraft適用、互換・失敗保護テスト、文書と正式公開。
## Non-Scope
対戦種別の自動判定、シーズンからの推定、手動戦績の初期値、既存戦績の更新、DBschema、録画方式、実利用データ操作。
## Chosen Approach
interaction.auto_watch_default_duel_typeを追加し既定other。other/ranked/event/room/soloの5値。監視開始時に既存save_settingsで一括保存し、frozen defaultsへ渡す。新規成功自動録画draftの既存duel_typeへ適用する。希望先後の右へ表示。
## Acceptance Criteria
- AC1: 対戦種別5候補を日本語表示し監視開始時に保存、画面再生成で選択復元。小画面/DPIでも操作可能。
- AC2: 旧設定にキーがなくてもotherで読み込む。全5値roundtrip。不正値は拒否し元設定不変。既存.previousとatomic失敗時の元内容保護を検証。
- AC3: 開始時の値は監視中の設定変更に左右されない。新規成功録画へ適用、手動録画/既存戦績/失敗・破棄の挙動維持。
- AC4: 関連回帰、Ruff、全unittest成功。版/文書整合。3EXE build/smoke、正式Release、公開7asset/hash/再取得3EXE smoke、CIとIssue/Milestone closure成功。
## Test Requirements
設定の5値/欠落/不正/書込失敗、defaults正規化、監視snapshot、成功draft/既存保護/手動、GUI選択保存と復元/保存失敗時非開始。既存録画画面の実widgetサイズテストへ項目を追加。
## Risks
層間の追加漏れと旧設定互換。保存処理自体は既存の検証・退避・atomicに接続する。
## Rejected Alternatives
シーズン推定や既存戦績の一括更新は依頼外。
## Deferred Solution Queue Intake
既存別件候補Keep、追加なし。
## Implementation Handoff
W1単一Issue: 4層を接続する小規模な縦断追加。背景は毎回対戦種別を手入力する負担。Scope/AC/Test Requirementsは上記。依存なし。録画・保存方式を変更しない。
## Configuration Compatibility / Rollback
追加キーのみ、旧ファイルの自動書換/一括移行なし。保存時は検証後app.toml.previousへ元バイト列を退避しatomic置換。失敗時は元app.tomlを保持。旧版は未知キーを無視できるが旧版で保存すると追加値を失う。必要ならアプリ停止後previousまたはバックアップから復元する。DB移行不要。
## Release Contract
required: Implementation, Tests, Configuration, UI, README, Architecture Docs, User Docs, CHANGELOG, Version Metadata, Commit, Push, Tag, Build, CI, Packaging, GitHub Release, Artifact Publish, Published Verification, Release Notes, Backward Compatibility, Issue/Milestone closure。
not-required: Database, Database Migration, Configuration Migration（欠落はotherで補完、移行処理なし）, API, CLI新コマンド, PR / Merge（既存main直接公開方式）。needs-investigationなし。
既存設定CLIの更新キー登録はConfigurationの範囲。配布検証はRelease CIの証拠を使用。既存の包括承認を継承し再確認しない。
