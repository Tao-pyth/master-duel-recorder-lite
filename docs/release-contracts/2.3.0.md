# V2.3.0 Release Contract

## Release Goal

PySide6 GUIで、v1.xから後退した実操作と状態フィードバックを回復し、デッキ・タグ・シーズン・戦績管理・テンプレート・信頼性画面を「表示だけ」ではなく実際に編集、確認、実行できる状態にする。

## Scope

1. 状態表示と開催中シーズン
   - 左下の固定「要確認」を、実診断結果または未確認状態に応じた表示へ変更する。
   - 録画画面の「開催中のシーズンを読み込み中」を `active_season_summaries()` などのサービス層へ接続する。
   - データがない場合は「開催中のシーズンなし」など、ユーザーが原因を判断できる表示にする。

2. デッキ名・タグ・シーズン編集
   - 一覧選択からフォームへ反映する。
   - 追加、保存、削除またはアーカイブを既存サービス層へ接続する。
   - DB更新を伴う操作は既存DataProtection方針に従い、危険操作や削除は確認を出す。
   - カラーコード露出をやめ、スウォッチと利用者向けラベルで表示する。

3. 戦績管理の実操作復旧
   - 手動追加、戦績編集、一括編集、未完了処理、表示列、重複候補、YouTube投稿導線を、案内表示止まりから実ダイアログまたは明確な実操作へ戻す。
   - ボタンが多いツールバーは、主操作、補助操作、危険操作、表示/フィルター操作に分け、アイコン+短いラベル+ツールチップで整理する。

4. テンプレート画面と信頼性画面
   - テンプレート画面から接続、切断、更新、privateテストを外し、投稿テンプレート編集と投稿準備キューに責務を絞る。
   - YouTube接続管理は設定画面へ集約する。
   - 信頼性画面の状態更新、初回導入確認を実処理へ接続し、結果を表示する。

5. UI基盤
   - ボタン、プルダウン、テキスト入力、日付入力の縦幅を統一し、操作領域を確保する。
   - 日付入力はカレンダーピックであることが分かる表示にする。
   - 選択行ハイライトとデータ色を分離し、選択時にデータ色が変わったように見えない表現にする。
   - 長時間処理にはPySide6のworker/threadまたは非同期UI更新を使い、処理中/完了/失敗を示す。

6. YouTubeアップロード
   - 実行ボタン押下後にUIを固めないバックグラウンド実行へ移行する。
   - 最小範囲は、実行中表示、二重実行防止、完了/失敗表示、既存の二重投稿防止契約維持とする。
   - 永続ジョブ管理、キャンセル、詳細な再試行ポリシーは今回の必須範囲に含めない。

## Non Goals

- SQLite schema変更
- DB migration
- 設定migration
- OBS Plugin / OBS WebSocket依存追加
- 録画ファイル、queue、manifest、OAuth資格情報の形式変更
- DADSのWebコンポーネントをQtへ完全移植すること
- すべてのv1.xポップアップを一度に完全再現すること
- YouTubeアップロードの永続ジョブ管理、キャンセル、詳細再試行ポリシー
- V1.0.0へのバージョン変更

## Chosen Approach

既存サービス層をGUI境界として維持し、PySide6画面の未接続部分をサービスAPIへ接続する。まず実操作回復と状態表示を優先し、その後に共通UI寸法、アイコン、カラー、日付、ローディングを整える。

DADSはデスクトップQtへ直接移植せず、ボタン階層、操作領域、ラベル、セレクトボックス、日付ピッカー、進行中表示の考え方をMDRLの操作密度に合わせて採用する。

## Acceptance Criteria

- 左下ステータスが固定「要確認」ではなく、正常、未確認、注意、失敗のいずれかを根拠付きで示す。
- 録画画面で、当日を含む有効シーズンがある場合は開催中シーズンが表示され、ない場合は「開催中のシーズンなし」と分かる。
- デッキ名画面で、一覧選択、追加、保存、削除が実操作として成立し、変更後に一覧が更新される。
- タグ画面で、一覧選択、追加、保存、削除が実操作として成立し、変更後に一覧が更新される。
- シーズン画面で、一覧選択、追加、保存、アーカイブまたは削除、レポート表示が実操作として成立する。
- 日付入力はカレンダーピックで選択でき、ボタン/プルダウン/日付入力の縦幅が揃っている。
- カラー列にカラーコードを主要表示として出さず、スウォッチと利用者向け情報で表現する。
- 表の行選択時に、データ色が変更されたように見えない。
- テンプレート画面には接続、切断、更新、privateテストボタンが表示されない。
- 信頼性画面のクリック可能な操作は、クリック後に状態更新、初回導入確認、または明確なエラー表示を返す。
- 戦績管理の主要操作は案内表示だけで終わらず、実ダイアログ、実処理、無効状態、または実装対象外理由のいずれかを返す。
- 戦績管理の多ボタン領域は、アイコン、短いラベル、ツールチップ、操作グループにより視認性が改善される。
- YouTubeアップロード実行中にUI threadが固まらず、実行中、完了、失敗がUIに表示される。
- 既存user_data、SQLite、録画ファイル、queue、manifest、OAuth資格情報を削除、初期化、上書きしない。
- テストまたはGUI smokeが、未接続ボタン、固定「要確認」、開催中シーズン未表示、編集保存不能の少なくとも主要ケースを検出できる。

## Risks

- 1リリースで扱う画面が多いため、Issue分割とDependency Orderを守らないと検証漏れが起きる。
- DB更新操作は既存データ保護を崩すリスクがある。
- YouTubeアップロードの非同期化は二重投稿や例外伝搬の扱いを誤ると信頼性を落とす。
- UI改善を優先しすぎると、実操作復旧が遅れる。
