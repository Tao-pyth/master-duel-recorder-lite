# V2.7.10 Release Contract


## Inputs
現行v2.7.9の音声設定再現調査。Issue #639、#640。

## Release Goal / Target Version
音声入力の候補更新が選択を変えず、有効な設定をキー順に依存せず保存できること。target_version: v2.7.10（既存機能のFix）。

## Scope / Implementation Handoff
W1 音声候補更新: 現在の選択を復元する。未検出でも元IDを保持し、未検出と案内。列挙失敗/0件/重複候補/未保存選択を扱う。更新途中のsignalによるdirty誤表示を防ぎ、保存済み・未保存状態を維持。
W2 設定一括検証: CONFIG_FIELDSの既存parserで全値を変換し、最終AppConfigを一回validateして既存atomic saveへ渡す。単項目updated_configのAPI・検証を維持。未知キー/型エラー/無効な最終状態は保存せず、既存configと.previousを保護する。
W1/W2は独立したIssueへ登録。両方を1回のGUI操作回帰で結合検証する。

## Acceptance Criteria / Test Requirements
- [ ] 同一候補の再列挙・順変更・重複・0件・消失・再出現で元選択を保持。未検出時は案内。列挙失敗でも保持。
- [ ] 候補更新だけでは保存済み設定がdirtyにならない。未保存選択はdirtyのまま、明示保存時のみ書き込む。
- [ ] process/noneからdevice/systemへmode-first/input-firstの両順で保存できる。逆方向にinputを空にするbatchも順序に依存しない。
- [ ] 不正batch/未知キー/保存失敗でconfigと.previousの内容が変わらない。単項目CLI向け更新は不正な中間状態を許さない。
- [ ] 実Qtで選択→候補更新→保存→再読込を確認。Ruff、全unittest、3EXE build/smoke、公開7asset hashと再取得3EXEsmokeを完了。

## Non-Scope
音声キャプチャ方式、OS候補列挙処理、DB/設定形式、資格情報、既存利用者のデータ変更、他画面の機能追加。#629実利用評価は今回の条件に含めない。

## Chosen Approach / Rejected Alternatives
候補は選択文字列を退避し既存の選択肢へ戻す。未検出の選択を黙って別候補へ切り替えない。一括変換用の小関数を追加して単項目関数をその利用者にし、parser/validateの重複を避ける。キー順だけの対症修正やvalidation無効化は不採用。

## Risks
設定一括更新に関係する他の相関フィールドも最終状態で検証される。未知キー、不正parser、無効組合せ、単一項目契約、atomic書込失敗の既存/追加回帰を確認する。

## Deferred Solution Queue Intake
既存の全画面監査は過去完了を維持し、新たな不具合の再訪として扱う。短期preroll/タイムラインの過去完了は維持。旧3機能と競合差別化/長時間録画はKeep。新しい保留項目なし。

## 保存失敗ACの補足（既存契約の確認）
Actのコード照合で、既存save_app_configは現設定を.previousへ退避してから現ファイルを置換すると確認した。したがって最終置換失敗では.previousが直前の現設定に更新されるのが既存仕様である。「保存失敗で.previousの内容が変わらない」は保存呼出前/退避前の失敗に適用し、最終置換失敗のACは「現設定が不変で、.previousに有効な現設定のバックアップが残る」と補足する。実装範囲は既存atomic保存を維持し、保存方式を変更しない。test_final_replace_failure_keeps_current_config_and_valid_backupで実際のos.replace失敗を検証する。既存保存契約に沿った検証の精密化で、操作承認を再要求しない。
