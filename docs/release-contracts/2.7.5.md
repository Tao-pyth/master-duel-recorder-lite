# Release Contract 2.7.5

## Summary

V2.7.5 delivers a compact review duel input workflow. It keeps the V2.7.x line and does not change database, configuration, recording, or upload behavior.

## Scope

- Compact the review screen's duel input tab.
- Show `status`, `result`, `play_order`, and `coin_face` as one-row segment buttons.
- Keep duel type and season as combo boxes.
- Keep own deck and opponent deck as editable candidate combo boxes.
- Route the battle history `編集` button to the review screen's `戦績入力` tab when a recording exists.
- Preserve the standard duel editor for manual/no-recording duel records.
- Compact the standard duel editor with the same segment-button controls.
- Update GUI contracts, release notes, validation notes, and version metadata.

## Non-Scope

- No SQLite schema migration.
- No configuration schema migration.
- No recording command, FFmpeg command, or output path changes.
- No runtime data deletion or initialization.
- No OAuth, queue, manifest, or direct upload changes.
- No V2.8.0 or later version bump.
- No full responsive redesign of the review screen.

- Focused GUI contract tests for the edit-button route and compact segment fields.
- Review ViewModel regression tests.
- Full pytest.

- Version metadata updated to `2.7.5`.
- Release notes and validation notes updated.

## Acceptance Criteria

- Review screen `戦績入力` tab displays `状態`, `勝敗`, `先後`, and `コイン` as compact segment buttons on one row.
- Segment button selections are saved into the existing `DuelRecordValues` fields.
- Battle history `編集` opens the review screen with the `戦績入力` tab selected when the row has a recording.
- No-recording duel records still open the standard duel editor.
- Standard duel editor uses the same compact segment controls and has lower vertical minimum size than V2.7.4.
- Marker edit, timeline selection, clip export, and review playback routes remain available.
- Public GitHub Release artifacts download and verify as V2.7.5 after release.
