# Master Duel固有UI判定チェックリスト

実ゲーム画像や動画はリポジトリ、Issue、ログへ添付しません。ローカル動画とイベント時刻だけを`user_data/visual-dataset/manifest.json`へ記録します。

## 対応条件

- Windows 10/11、FFmpeg 6以上、Master Duel日本語UI
- 1920x1080ウィンドウ、または3440x1440フルスクリーン
- `visual_events_enabled = true`、`visual_maximum_fps = 2.0`以下
- ボーダーレスはゲームに設定がないため対象外

## ライブ対戦

1. メニュー、デッキ編集、設定画面で自動監視を開始し、録画が確定しないことを確認する。
2. コイントスで候補録画が始まり、盤面表示後に対戦として確定することを確認する。
3. 先攻・後攻が対戦記録へ保存されることを確認する。
4. ターン切り替えごとに候補が1件だけ作られ、同じ表示で重複しないことを確認する。
5. カード詳細、設定、大型召喚、チェーン中も録画が継続することを確認する。
6. VICTORY、LOSE、サレンダー後に勝敗が保存され、約3秒後に停止することを確認する。
7. マッチエラーでは候補録画を破棄し、次の対戦監視へ戻ることを確認する。
8. リプレイ再生ではライブ録画を開始しないことを確認する。
9. 手動録画では判定結果にかかわらず、録画開始と停止が利用者操作に従うことを確認する。

## オフライン回帰

```powershell
python scripts/evaluate_visual_dataset.py --manifest user_data/visual-dataset/manifest.json --fps 2 --markdown-out user_data/visual-dataset/report.md
```

台帳に提供動画14本、表示プロファイル、ライブ・リプレイ区分、開始・ターン・結果・エラーの許容時刻を登録します。レポートで種別ごとの適合率、再現率、時刻誤差、誤検出、見逃しを確認します。評価器が抽出画像を作成せず、元動画を変更しないことも確認します。

## 音声と負荷

30分以上の音声付き録画で映像・音声の継続時間差を確認します。解析遅延で破棄フレームが増えても録画とGUI操作が継続し、判定例外がFFmpegを異常停止させないことを確認します。

## 記録項目

- アプリ版、検出器ID・版、解像度、表示モード、UI言語
- 動画本数と総時間、イベント別の期待件数と検出件数
- 適合率、再現率、候補時刻のずれ、誤検出、見逃し、重複
- 録画の成否、FFmpeg終了コード、自動判定と音声の最終状態

## V0.23.0 Releaseゲート

### オフライン

1. 動画ID、用途、サイズ、SHA-256を固定したローカル回帰コーパスを2fpsで全区間評価する。
2. `standard-16:9-window`と`ultrawide-fullscreen`を分け、開始、盤面、ターン、結果、エラーのTP、FP、FN、適合率、再現率、平均絶対遅延を記録する。
3. V0.25.0の超横長コーパスは有効11戦の開始11/11、盤面11/11、結果11/11、負例3本の同イベント誤検出0を満たす。
4. 標準16:9の最新実動画がない場合は、自動テストで代替した範囲と未検証リスクをReleaseへ明記する。
5. 許容区間は原則2秒以内とし、広い仮注釈を精度合格の根拠にしない。
6. 保存済み実戦録画を修正後ゲートへ再利用する場合は`assume_started`で候補録画開始済み・盤面確定待ちを再現し、全動画を先頭から終端まで再生する。診断の`result_stopped`を正解とはせず、映像上の正規結果区間と決着前停止の負例を別に注釈する。

### 実戦

1. 初期3戦で自動開始、盤面確定、結果停止、次戦待機を3/3確認する。
2. 調整後10戦連続で同じ4項目を10/10確認する。
3. 10戦中に移動・リサイズ、前面喪失、オーバーレイを含め、誤停止しないことを確認する。
4. マッチエラーとリプレイを各1回確認し、正式履歴へ昇格しないことを確認する。
5. 数値診断ZIPに画像、タイトル、絶対パスが含まれないことを確認する。
6. 本検証後に誤判定を修正した場合、同じ保存済みセッションの全編再生で正規結果100%、既知偽陽性0件を確認できれば、利用者へ同内容の再撮影を要求しない。

試験開始前に同じPowerShellセッションで開始時刻を保持し、初期3戦と調整後10戦は別の開始時刻で集計します。

```powershell
$since = (Get-Date).ToString("o")
# GUIで自動監視を開始し、対象の連続試験を実施する
python scripts/validate_live_monitoring.py --since $since --required-consecutive 3 --json-out build/validation/live-initial-3.json --markdown-out build/validation/live-initial-3.md
```

初期調整後は`$since`を取り直し、`--required-consecutive 10`で最終試験を行います。終了コード0は最新の連続戦が全件、候補開始・盤面確定・結果停止・停止後3秒以上の監視継続を満たし、診断順序不正がない場合だけ返します。さらに結果停止後から次戦候補開始まで最大120秒を調べ、盤面スコア0.35以上が3件あれば「結果停止後も盤面継続」として不合格にします。候補破棄は対戦数から除外し、境界停止、通常停止、未完了、早期停止疑いは失敗として表示します。移動・リサイズ、前面喪失、マッチエラー、リプレイの操作事実は数値集計だけでは証明できないため、実施メモと併せて残します。

実動画または実戦の証拠が欠ける場合、単体テストが成功していてもV0.23.0を公開しません。
