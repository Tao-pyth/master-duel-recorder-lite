# 基本イベント自動判定 実画面チェックリスト

この確認では実ゲーム画像をリポジトリ、Issue、ログへ添付しません。専用のテスト用`user_data/`を指定し、録画とタイムラインの数値情報だけを確認します。

## 前提

- Windows 10/11、FFmpeg 6以上、Master Duelを16:9表示可能な状態にする
- `detection.visual_events_enabled = true`
- `detection.visual_maximum_fps = 2.0`以下
- `detection.visual_minimum_confidence = 0.70`以上
- GUIの環境診断で「画面イベント判定」がOKである

## 手順

1. メニュー画面で自動監視を開始し、10秒待っても録画と`duel_start`候補が作成されないことを確認する。
2. 1対戦を開始し、安定盤面の表示から約1.5秒後に自動録画が始まることを確認する。
3. 対戦途中で自動監視を開始し、開始演出なしでも安定盤面3フレームの合意後に自動録画が始まることを確認する。
4. GUIの自動判定状態が「実行中」となり、処理フレーム数が増加することを確認する。
5. 各ターン切り替え、結果画面を数秒表示して録画を正常停止する。
6. 録画履歴の「タイムライン」を開き、開始と結果が各最大1件、同じターン演出が重複していないことを確認する。
7. 候補時刻で動画を再生し、開始・ターン・結果とのずれ、actor、outcome、信頼度、検出理由を記録する。
8. 候補を確認または却下し、自動で`confirmed`になっていないことを確認する。
9. 任意ウィンドウ、モニター、デスクトップ録画では自動判定が無効と表示されることを確認する。
10. Master Duelウィンドウを一時的に最小化し、判定が劣化または停止しても録画ファイルが正常終了・再生できることを確認する。
11. CPU負荷とGUI応答を確認し、解析遅延時に破棄数が増えても録画時間と音声が継続することを確認する。

## 記録項目

- アプリ版、検出器ID・版、解像度、表示モード、UI言語
- 開始・ターン・結果の期待件数と候補件数
- 候補時刻のずれ、誤検出、見逃し、重複
- 録画の成否、FFmpeg終了コード、自動判定の最終状態

ゲーム画面の変更で再現性が失われた場合は、画像を公開せず上記数値と環境情報をV0.16.xのIssueへ記録します。

## V0.16.0実装時の確認記録

2026-08-09にWindows実機で次を確認しました。ゲーム画像と一時録画は保存せず、検証後に削除しています。

- FFmpeg `gdigrab`の`hwnd=`入力は終了コード`-5`（DWORD `4294967291`）となることを再現し、`title=masterduel`でのBMP取得成功を確認した
- 3440x1440の取得フレームを640x360へ正規化し、対戦盤面で`board=0.650`、`start_animation=0.068`を観測した
- 対戦盤面の単独フレームから`duel_start`、`turn_change`、`duel_result`を生成しないことを確認した
- 一時`user_data`で短時間録画と自動判定を同時実行し、録画完了、自動判定`stopped`、候補0件を確認した

## V0.16.5実装時の確認記録

2026-08-09に提供画像と起動中のMaster Duel実画面で次を確認しました。画像はリポジトリ、Issue、ログへ保存していません。

- 提供画像で`board=1.00`、`start_animation=0.01`、実画面で`board=1.00`、`start_animation=0.06`を観測した
- 開始演出なしの両画面を3フレーム合意へ通し、1・2フレーム目は候補なし、3フレーム目で`duel_start`確定を確認した
- 実画面の取得は管理対象FFmpeg 9.0を使い、取得失敗と破棄がないことを確認した

メニュー、デッキ編集、結果表示を含む一連の誤検出確認とターン・勝敗精度は利用者操作が必要なため、上記手順1から11をリリース後も継続します。
