## 実行時データ保護と本人操作

調査は実DBを読み取り専用で開いた。実運用DB・リポジトリ内の既存DB・OAuth client asset・ユーザー編集済みAGENTS.mdは、作業前後のSHA-256/サイズ/更新日時が一致した。実録画・queue・OSの実認証資格情報の削除/書換/初期化は行っていない。

実ログのHTTP400 invalid_grantを再認証が必要な状態として扱えることを検証した。失効理由の細分類は未確定。実Googleログイン同意と実動画投稿は未実施のため、実投稿成功を確認済みとはしない。

現在の旧版を閉じ、正式配布のGUIを起動して「設定 → YouTube → 連携する」で本人がブラウザ認証を行い、対象投稿を再試行する。詳細は[操作説明](../releases/2.7.20.md)。

初回のローカル提供ではCommit/Push/Tag/正式公開はnot-requiredだった。追加依頼ではmain反映、tag、main/Release CI、公開7assetと再取得検証、Issue/Milestone closureをrequiredへ変更。PRは既存main直接公開方式のため不要。
