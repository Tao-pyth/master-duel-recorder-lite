## 保存契約

- 使用回数は`duel_records.own_deck_id`と`duel_records.opponent_deck_id`を優先して集計する
- 旧データでIDが欠ける場合だけ、`own_deck`と`opponent_deck`の名称一致で補完する
- 使用回数は永続化せず、DB schema V17を維持する
- Tkinter UI baseline取得では検証用runtimeを使い、本番`user_data/`を初期化・上書きしない
- OAuth token、refresh token、client secret、認可コードを文書、画像、ログ、DB、queueへ保存しない

## GUI確認観点

- デッキ名管理画面に「使用回数」列が表示される
- 使用回数が多いデッキ名が上に表示され、同数時は名前順で安定する
- 戦績管理、統計、簡易入力、未完了処理、詳細入力、一括編集でデッキ候補順が維持される
- 戦績管理のデッキ名列に枠線付き四角スウォッチが表示される
- 明るいデッキ色と暗いデッキ色のどちらでもスウォッチが背景に埋もれない
- baseline文書内の主要ページ、内部ページ、ポップアップ画像リンクが実ファイルと一致する
