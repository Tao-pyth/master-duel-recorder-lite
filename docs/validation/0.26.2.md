## クリーン環境E2E

Windows TEMP配下の空の`LOCALAPPDATA`とアプリ配置先を使用し、既存の設定・DB・録画・FFmpegへ依存しない状態で検証する。

`python scripts/validate_v1_candidate.py --cli-exe dist/master-duel-recorder-lite.exe --expected-version 0.26.2 --json-out build/validation/v1-candidate-0.26.2.json`を実行し、次を確認した。

- 空の実行時ルートへ既定設定と全管理ディレクトリを作成
- 配布CLIで録画なし戦績を作成し、勝敗、先後、コイン、自分・相手デッキ、種別、タグ、メモを再取得
- 固定11列、UTF-8 BOM、CRLFのCSVを出力し、同じ戦績をプレビュー・更新
- サンプルCSVを出力して再読込
- CSV取込前バックアップと手動バックアップを作成
- DB、外部キー、録画参照、管理データの整合性診断が正常
- クリーンアンインストール後に実行時ルート全体が消失
- 実行時ルート外の確認ファイルと、削除指定していない配布CLI EXEを保持

最初の検証実行では、Windows one-file版の終了後クリーナーが非同期であるのにCLI終了直後に削除判定して失敗した。製品処理は継続して正常削除していたため、検証スクリプトを最大10秒の完了待機へ修正し、再実行で全項目に合格した。

## 公開ゲート

GitHub CI、Windows EXE Release workflow、公開Release資産、公開SHA-256は、`main` pushと`v0.26.2`タグ後にIssue #377へ実行URLと資産digestを記録する。ローカル検証結果と公開ビルドのSHA-256はPyInstallerの非決定的要素により一致を要求せず、各配布元のsidecarとGitHub asset digestの一致を確認する。

## 既知制約

- 自動画面判定は日本語UIの1920x1080ウィンドウと3440x1440フルスクリーンを対象とする
- 標準16:9のコイントス、リプレイ、マッチエラー実動画は固定コーパスに含まれない
- 最新結果判定は保存済み12録画の全編2fps再生で、正規結果11/11、偽陽性0/1、Precision/Recall 1.000を確認した
- Process LoopbackはWindows build 20348以上を対象とし、マイクとの同時ミックスは対象外とする
- EXEはコード署名されていないため、GitHub Release、SHA-256、provenanceで配布元を確認する
- YouTube直接アップロードとOAuthはV1.0.0の対象外とする
