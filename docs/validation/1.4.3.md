## 更新失敗原因の整理

V1.4.1/V1.4.2で見えた`Failed to load Python DLL ... _MEI...\python313.dll`は、公開Releaseから手動ダウンロードした同じGUI EXEが起動できたため、Release assetそのものの壊れ方ではなく、旧アプリ内更新の適用方式に寄った問題と判断します。V1.4.2の「取得後GUI EXE事前スモーク」は候補EXEの単体起動を確認できますが、旧GUIプロセス終了後に自己置換し、次回起動するまでの展開ディレクトリ、ファイルロック、置換タイミングの問題までは保証できません。

V1.4.3では置換をGUI本体から分離し、専用updaterがGUI終了を待ってから候補SHA-256を再確認し、現在EXEを`.previous`へ退避、候補を`.staged`経由で置換します。置換後に更新後GUIを`--smoke-test`で起動し、失敗時は旧EXEへ戻します。これにより通常導線は手動更新ではなく、アプリ内の自動更新を維持します。

## 外部ゲート

実YouTube private投稿E2Eは、配布EXE公開後にユーザーのGoogleアカウント、YouTubeチャンネル、OAuth同意画面の公開またはテストユーザー登録、YouTube Data API quotaが揃った状態で確認します。この検証では`client_secret`、access token、refresh tokenを配布物、設定、queue、manifest、ログへ含めない契約を自動テストで確認しています。
