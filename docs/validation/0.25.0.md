## 2026-08-15追加2セッション

利用者から申告された5件を確認したところ、SQLiteには2セッション・6録画が記録されていました。前半セッションは4録画すべて`result_stopped`、後半セッションは2録画のうち1件が`result_stopped`、1件が`boundary_stopped`でした。後半1件は結果を検出できないまま次対戦の`READY`まで録画を継続し、その次の録画は開始演出から始まっており、同じ次対戦が2ファイルへ分断されていました。境界検出から再検出開始まで約8秒の欠落があるためIssue #366を登録しました。

現行集計器で2セッションを再評価した結果は6試行中5件合格、境界停止1件不合格、最大連続成功4、最新連続成功1/3、実効fps最小1.941・平均1.944でした。境界停止後に次候補を確認できているため監視復帰は成功していますが、前対戦の結果停止条件を満たしていないため公開ゲートは未達です。

fix340では境界候補を前録画の停止だけで消費せず、時間窓合意が成立した同じ監視ループで前録画を停止し、同じ画面座標と候補から次録画を開始します。`boundary_stopped`には境界時のスコア・合意を、`boundary_handoff_started`には引継ぎ時間を保存します。前対戦の結果見逃しは実戦ゲート上の失敗として維持し、次対戦の引継ぎ成功とは分離して集計します。修正後の実戦ログは未取得のため、fix340による初期3戦と10戦連続試験が必要です。
