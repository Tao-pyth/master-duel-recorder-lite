- 確認済み使用/明示非使用/不明、1対戦単位、初動条件、期間・種別・hidden・正常録画、候補参考値の分離を検証。
- 実子プロセスで正常完了、非ゼロ終了、壊れたJSON、応答停止、入力変更、OFF・録画開始中断、checkpoint後の同ジョブ再開、OS録画lock、二重managerの競合を確認。
- 共通applicationで正常完了した手動停止・自然終了・自動録画停止の3経路だけが投入されること、分析失敗が録画完了を変更しないこと、詳細表示候補の使用確定には使用者と行動を要求することを検証。
- 旧設定はOFF/2fpsを補完し、読込で書き換えない。新設定のatomic保存と、不正fps/bool/非有限値で既存値を置き換えないことを確認。

- GUIの対象編集/無効化、訂正/確定/却下、実使用時刻/初動/非使用、seek/マーカー、統計条件を実applicationと隔離SQLiteへ接続。未保存編集は進捗pollで上書きしない。終了はserviceへ委譲してworkerを回収する。
- 100/150/200%の日本語画面を980×640logicalのmain、400×480logicalのカードレビューで確認。縦scrollで全主要操作へ到達する。fontはQA用にWindowsのMeiryoを登録し、テスト終了時に復元する。
- CLIの対象保存/別名/無効化/競合、ジョブ/結果、設定OFFの拒否、有限待ちと終了、DBを触らないモデル診断、CLI/GUI内部worker routeを検証。

## 認識評価の基準

固定87名称画像と5ログ切り出しの探索試験を基準にする。日本語参照はAI視認による暫定参照で、人による全イベント正解データではない。

|方式|読める名称の完全一致|87名称の処理時間|名称試験peakRSS|
|---|---:|---:|---:|
|既存Windows OCR（調整後）|10/33|別条件の既存試験|別条件の既存試験|
|PP-OCRv4日本語・max736|5/33|12.43秒|140.2MiB|
|採用PP-OCRv6 small・max736|14/33|9.71秒|172.2MiB|

採用方式で空画面49件中47件は空文字。残り2件を使用イベントの誤検出とは数えない。5ログではカード名文字列8/8、行動文字列7/8、抽出行7件。参照と比較可能だった6行は名称5/6、行動6/6、色fallbackを含む使用者6/6。全行が抽出できた結果ではない。ログ試験は3.681秒、peak203.6MiB。名称とログの短時間試験を足して全動画時間を予測しない。

全イベントPrecision/Recall、実ゲームFPS、他解像度・UIの網羅精度は未測定。OCRconfidenceは使用確率ではない。

正式Pillow11.3環境でも、同じ5ログcropのOCR文字列は探索環境と全件・順序まで一致した。製品parserの名称・行動・使用者の限定照合は、汎用の行動表記正規化後、別名なし7/8表示。利用者が今回の誤読を見て別名を1件登録した追加条件では8/8表示になった。モデル・OCR結果・名称類似度閾値を変えた改善ではない。表示8行は重複を含む参照であり、全動画の使用イベント精度ではない。

過去ログの共通表示の同じID保持、同じcrop連続表示、隠れた後の再表示、既知系列の再表示での重複抑制を実OCR行で確認した。人工的な表示遷移の限定試験で、実使用時刻やゲーム内部IDを保証しない。未分類候補が後の分類済み使用と別に残る場合があり、確認前の候補として扱う。

## 実録画と録画優先

固定した実録画3本を原ファイルread-only、1worker、試験用DBへ解析する。前後のSHA/size/mtimeを照合する。処理時間・CPU・RSS、coverage、候補・不明・重複と時刻意味を保存する。

初回の実録画試験で、OpenCV read終了位置6407とreported frame count9196の不一致を検出し、ジョブを失敗扱いにした。ffprobe全count6407、FFmpeg全復号exit0/警告なし、最終PTS306.500＋frame duration0.033＝容器306.533秒で、正常VFRを誤判定していたことを確定した。終端を実PTS到達で検証する実装へ修正し、推定countとの差をcoverageへ残す。原動画3本の前後SHA/size/mtimeは不変。

同じ録画の旧checkpointを再開する実試験は3.08秒、6383→6407frame、611→614sampleで終了0。保存PTSを実際に照合し、305521/306021/306521msの3sampleだけを追加した。OpenCVの末尾時刻と容器長の差21msは許容50ms以内として記録。名目frame seekでは約89秒前に戻る問題も是正した。旧checkpointには実測sample gapが無いため、その項目を不明として扱う。最初からの全3本測定は継続中。

生成lavfi録画による録画lock中断、正常録画出力、同ジョブの途中再開と応答時間は検証継続中。再開後のworker metricsはその実行分であり、前の中断processを含む全ジョブ時間ではない。

## 全体・配布

最終sourceの全unittestは786件、119.365秒、失敗0、skip1、ResourceWarningをerror扱い。任意のFFmpeg録画/音声試験と投稿準備試験もONにして全体へ含めた。残るsymlink保護試験1件は実行環境でsymlinkを作成できないためskip。Ruffと差分チェックは合格。以後のGUI smoke設定ID2件のmetadata修正は、GUIcontract13＋実main設定導線1の14件で追加検証した。

初回780件の統計header寸法失敗2件は、新GUIテストのglobalfont残留を修正して解消。card9→既存統計2を同processで再検証し、header AC96を緩めず維持した。初回の失敗ログも保存している。

隔離build環境はPython3.13、RapidOCR3.10.0、ONNX Runtime1.31.0、OpenCV5.0.0.93、NumPy2.5.4、Pillow11.3.0、PySide6.10.3。探索試験のPillow12.3との差を正式環境の実OCRで確認した。通信APIを例外化した汎用日本語動画の推論が成功する。

3EXEのbuild/既存smokeと、CLI/GUI同梱モデルの診断・生成日本語文字の実推論が成功。モデル2個の合計31,163,977bytes、固定SHA・設定2・ライセンス/出所6をarchiveで照合する。ローカルにOAuth client assetと環境設定が無いため非require modeで検証し、正式Release CIは既存secrets＋require modeを維持する。最新sourceと対応する最終再buildの確認は継続中。

配布onefileの起動用processだけを止めると実解析processが残る問題を再現し、Windowsの直親とmanager所有者の生存を監視するよう修正。親managerを生存させたまま中断し、CLI全3子0.526秒、GUI全2子0.441秒、source venv全3子0.103秒で全終了とwaitingを確認した。強制cleanupなし、close正常、生成入力不変。これらは所有workerの停止応答の試験で、実ゲームFPSや実Recorder開始を測る試験とは分ける。
