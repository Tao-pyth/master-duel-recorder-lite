## クリーン環境E2E

V0.26.2で追加した`scripts/validate_v1_candidate.py`をV1.0.0のローカル配布候補へ再実行し、次を確認した。公開後はGitHub Releaseから再取得したCLIへ同じ検証を適用する。

- 空の実行時ルートへ既定設定と全管理ディレクトリを作成
- 配布CLIで録画なし戦績を作成し、勝敗、先後、コイン、自分・相手デッキ、種別、タグ、メモを再取得
- 固定11列、UTF-8 BOM、CRLFのCSV出力・プレビュー・更新と、サンプルCSV再読込
- CSV取込前バックアップ、手動バックアップ、DB・外部キー・録画参照・管理データ整合性診断
- クリーンアンインストール後に実行時ルート全体を削除
- 実行時ルート外の確認ファイルと、削除指定していない配布CLI EXEを保持

## 公開ゲート

GitHub CI、Windows EXE Release workflow、provenance、公開Release資産、公開SHA-256は、`main` pushと`v1.0.0`タグ後にIssue #380へ実行URLとasset digestを記録する。公開CLI・GUIは再ダウンロード後にsidecar一致を確認し、公開GUIスモークと公開CLIのクリーン環境E2Eを再実行する。

## 既知制約

- 自動画面判定は日本語UIの1920x1080ウィンドウと3440x1440フルスクリーンを対象とする
- 標準16:9のコイントス、リプレイ、マッチエラー実動画は固定コーパスに含まれない
- 最新結果判定は保存済み12録画の全編2fps再生で、正規結果11/11、偽陽性0/1、Precision/Recall 1.000を確認した
- Process LoopbackはWindows build 20348以上を対象とし、マイクとの同時ミックスは対象外とする
- EXEはコード署名されていないため、GitHub Release、SHA-256、provenanceで配布元を確認する
- YouTube直接アップロードとOAuthはV1.0.0の対象外とする
